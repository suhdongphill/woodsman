## 0. 무엇을 봤고 무엇을 안 봤나

⚠ **화면 점검(브라우저)은 하지 않았다.** 관리자 로그인 확인을 받지 못해 건너뛰었다.
따라서 **아래는 전부 코드·문서·운영 응답 실측에 근거한 것**이고,
"관리자 화면에 빈 화면·에러가 없다"는 이번 점검이 **확인하지 못한 사항**이다.

본 것:
- `git log`·`git status`·`gh run list`
- `npm run typecheck` (통과) · `npm run test` (**39파일 577개 전부 통과**)
- 운영 경로 15개 상태코드 실측 — 전부 기대값과 일치(`/board` 404, `/admin` 307)
- 운영 응답 헤더 실측 (`curl -I`) ← 8/7 기록이 "다음 점검 1단계에 넣어라"고 남긴 항목
- 운영지침·개발요구서 v2·CLAUDE.md 대조 (에이전트)
- 보안 — 유출·권한·입력·리다이렉트·의존성·최신 CVE (에이전트)

### ⚠ 점검 중 운영본에 보낸 요청 (밝혀 둔다)

반증 검증 에이전트가 C2·C3을 확인하려고 **운영본에 실패 로그인 12회를 실제로 보냈다**
(`/api/auth/csrf` → `/api/auth/callback/credentials`). 12회 모두 302였고 429·잠금·지연이 없었다 —
이것이 C2·C3의 실측 근거다. **데이터는 바뀌지 않았지만, 사전 합의 없이 운영 인증 경로를 두드린 것은 맞다.**
다음부터 이런 실측은 미리 묻는다.

## 4. ✅ 8/7 지적 중 **해소된 것** (재확인)

안 본 것과 괜찮은 것을 구분하려고 남긴다.

- 가입 액션이 화면과 별개로 `signupEnabled`를 **서버에서 다시 확인**한다
- `/api/view`가 본문 크기·출처·경로 화이트리스트 문지기를 통과해야만 쓴다
- **서버 액션 26개 파일 전부** `requireAdmin`/`requireUser`를 먼저 부르고, `/admin/layout.tsx`도 중복으로 건다
- 가입 폼은 `role`을 받지 않고 항상 `USER` 고정 (권한 상승 없음)
- **SQL 전부 `?` 바인딩**, 컬럼·테이블명은 코드 상수에서만 생성
- `/go/[target]`은 목적지를 쿼리로 받지 않는다 (오픈 리다이렉트 없음)
- **커밋된 시크릿 없음** — `.env` 미추적, `seed.d1.sql`은 `.gitignore:42`로 차단, `NEXT_PUBLIC_` 사용처 **0건**, 소스에 API 키 리터럴 없음
- 로그인 실패 사유를 구분하지 않는다 (계정 존재 여부 노출 없음)

⚠ (5)·(6)은 **기능을 확장할 때 가장 먼저 깨지는 자리**다. 테스트로 계속 고정해 둔다.
