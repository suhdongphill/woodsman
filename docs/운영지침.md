# Woodsman 운영지침

> 개발이 **중간중간 끊겨서** 진행되기 때문에, 그때그때의 지시가 앞의 결정과 어긋날 수 있다.
> 이 문서는 그 어긋남을 잡기 위한 기준선이다. `점검` 스킬이 이 문서를 근거로 대조한다.

---

## 0. 지시가 이 문서와 어긋날 때 (⚠ 가장 중요)

작업 지시가 아래 원칙과 충돌하면 **조용히 따르지 않는다.**

1. 어긋나는 지점을 한두 문장으로 **먼저 말한다** — 무엇과 무엇이 부딪히는지.
2. 그래도 진행하겠다고 하면 **그대로 진행한다.** 결정은 사람이 한다.
3. 진행했으면 이 문서와 `CHANGELOG.md`를 **같이 고친다.** 문서가 뒤처지면 다음 점검이 거짓말을 한다.

바꾼 원칙을 문서에 반영하지 않고 넘어가는 것이 가장 나쁘다.

## 1. 설계사상 — 모든 것은 admin이 유연하게 운영한다

**코드를 고쳐야만 바뀌는 운영값을 만들지 않는다.** 사이트의 성격·정책·문구는
관리자 화면에서 바꿀 수 있어야 한다.

| 무엇을 | 어디서 바꾸나 |
|---|---|
| 가입·커뮤니티·댓글 개방 | `/admin/comments` 스위치 |
| 승인제 · 로그인 요구 · 금지어 | `/admin/comments` |
| 모의/실계좌, 환율, 홈 문구, 연락처, 티스토리 주소 | `/admin/settings` · `/admin/home` |
| 콘텐츠·투자일지·포트폴리오·거시 지표·버블 점수 | 각 관리자 화면 |

이 사상에서 나오는 세 가지 금지:

- ⚠ **목업으로 되돌리지 않는다.** 화면이 `lib/mock.ts`를 읽는 순간 관리자 편집이
  조용히 무효가 된다. 2026-08-06에 다섯 곳, 08-07에 댓글까지 여섯 곳을 겪었다.
- ⚠ **죽은 버튼을 두지 않는다.** 누를 수 있으면 동작해야 한다. 눌러도 아무 일이 없으면
  운영자는 처리했다고 믿고 넘어간다 — 숨긴 줄 안 댓글이 계속 노출되는 것이 그 값이다.
- ⚠ **같은 판단을 두 번 구현하지 않는다.** 화면과 서버가 각자 판단하면 한쪽이 반드시
  뒤처진다. 판단은 `src/lib/*.ts` 순수 모듈 하나에 두고 양쪽이 그걸 부른다.

## 2. 지금의 단계와 앞으로

`src/lib/site-status.ts`의 로드맵과 **말이 맞아야 한다**(점검 대상).

| 단계 | 상태 | 무엇을 여는가 |
|---|---|---|
| 01 혼자 기록한다 | **현재** | 1인 계좌·투자일지 공개. 가입·게시판·댓글 잠금 |
| 02 원칙을 나눈다 | 예정 | 회원가입 + 게시판·댓글. **게스트(비로그인) 피드백도 받는다** |
| 03 파이프라인 도구 | 예정 | 개인 포트폴리오·배당 캘린더·리밸런싱 점검 |
| 04 서비스화 | 예정 | 법인 설립, 유료 여부는 그때 공지 |

**게스트 댓글은 이미 구현돼 있다.** `/admin/comments`의 "댓글 작성 시 로그인 필요"를 끄면
비로그인 방문자도 쓸 수 있고 작성자는 `익명`으로 남는다. 새 코드가 필요한 일이 아니라
스위치를 켜는 일이다 — 1장의 사상 그대로다.

⚠ **가입·게시판을 열기 전에 `/privacy`를 먼저 갱신한다.** 지금 방침에 "회원정보를 수집하지
않는다"고 명시돼 있어, 여는 순간 방침 자체가 형식 미비가 된다.

## 3. 공개 화면에서의 신원 (2026-08-07 결정)

- 공개 화면의 운영자 표기는 **필명 `Woodsman`**. 정식 오픈 전까지 실명을 앞에 두지 않는다.
- ⚠ **예외는 `/privacy`의 개인정보 보호 책임자 한 곳뿐이다.** 개인정보보호법상 책임자는
  실명 공개가 원칙이라, 여기까지 필명으로 바꾸면 방침이 형식 미비가 된다.
- 저장소가 공개(`suhdongphill/woodsman`)라 **로그·커밋 메시지에도 실명을 적지 않는다.**
- 남아 있는 실명 흔적(GitHub 계정명, `suhdp@naver.com`, `suhdp.tistory.com`)은
  **의도적으로 남긴다** — 실제 사업을 할 때 필요한 자산이다. 지우지 말 것.

## 3-1. ⚠ 변경은 **한 번에 하나씩** 배포한다 (2026-08-30 결정)

여러 변경을 묶어 올리면 `/admin/releases`의 판정이 **「겹친 변경 · 무엇 때문인지 가릴 수 없음」**이
된다. 판정기의 결함이 아니라 **사실**이다 — 같은 날 다섯 개를 바꾸면 무엇이 효과를 냈는지
가릴 방법이 실제로 없다.

- 작업이 여러 개 쌓였으면 **커밋은 나눠 두되 push는 하나씩** 한다.
- **지표를 움직일 만한 변경**은 `/admin/releases`에 **가설과 함께** 기록한다.
  ⚠ 가설은 결과를 보기 **전에** 적는다 — 보고 나서 쓴 가설은 항상 맞는다.
  ⚠ **잴 게 없는 변경은 기록하지 않는다**(2026-08-30 정정). 파비콘·오타 수정 같은 것을 넣으면
     목록이 잡음이 되고, 더 나쁘게는 **겹침 판정을 늘려** 정작 재고 싶은 변경의 판정을 망친다.
     처음에는 "예외 없이 기록"으로 정했다가 실제로 넣어 보고 뒤집었다.
  기준: **배치·문구·메뉴·디자인·콘텐츠**는 기록한다. **고침(FIX)은 지표에 영향이 있을 때만.**
- 급한 수정(FIX)과 실험할 변경이 섞이면 **급한 것을 먼저 단독으로** 올린다.

⚠ 2026-08-30에 홈 재편·UI 개편·SEO를 하루에 몰아 배포했다. 그날 것은 전부 **기준선으로만**
남았고, 무엇이 무엇을 움직였는지는 영영 알 수 없다. 이 규칙은 그 대가로 생겼다.

---

## 3-2. ⚠ 화면을 **독자의 눈으로** 본다 (2026-08-30)

만든 사람은 화면을 **알고** 본다. 그래서 애매한 것이 안 보인다.
배포한 뒤에는 **처음 온 사람인 척** 한 번 훑고, 되묻게 되는 자리를 고친다.

되묻게 되는 자리의 예 (실제로 나온 것들):

- **주어가 없다** — 「안정 · 지표 5개 종합」. *무엇이* 안정인가? → 「침체 신호 안정」
- **0이 셋** — 「기록 개월 0 · 투자일지 0건 · 리밸런싱 0회」는 "아무것도 없는 사이트"로 읽힌다.
  ⚠ 0을 **감추자는 게 아니라**, 실제로 있는 것(추적 중인 지표)을 대신 말하자는 것이다.
  기록이 시작되면 원래 셋으로 돌아온다.
- **이름만으로 뜻을 모른다** — 「시스템」 토글. 무엇의 시스템인가? → 「화면 시스템」

⚠ 고칠 때 **없는 것을 있다고 적지 않는다.** 애매함을 없애자고 과장하면 더 나쁘다.

## 4. 목적의 우선순위

**1순위는 티스토리 블로그로 트래픽을 보내는 것.** 체류시간도 광고 수익도 아니다.

- 자리 경쟁이 붙으면(글 본문 끝) 티스토리 CTA가 **광고보다 위**에 온다.
- 성과 지표는 `/admin` 최상단의 "티스토리로 넘어간 클릭"이다. 페이지뷰가 아니다.
- 티스토리 원문 글은 canonical을 원문으로. 전문을 복제하지 않는다.
- 사이트 고유 콘텐츠(계좌 공개·투자일지)가 검색 유입을 만드는 미끼다. 약화시키지 않는다.

## 5. 정직하게 말해야 하는 것들

숫자를 공개하는 사이트라, 숫자에 대한 거짓말이 신뢰를 통째로 무너뜨린다.

- ⚠ 계좌 숫자가 나오는 화면에는 **모의/실계좌 표시**를 반드시 붙인다(`DataModeNotice`).
  기본값은 모의(`PAPER`). 설정을 못 읽었다고 실계좌로 보이면 안 된다.
- ⚠ 수기 입력 시세는 **기준일과 함께** 낸다(`priceAsOf`). 날짜 없는 숫자는 실시간으로 읽힌다.
- ⚠ 자동 수집 시세와 수기 시세가 한 화면에 섞이면 구분해서 표시한다.
- 실패했을 때 "값이 없음"과 "읽지 못함"을 같은 화면으로 만들지 않는다.
- 버블 점수는 결측을 분모에서 뺀다. 안 본 지표를 0점으로 치면 "안 본 것"이 "괜찮은 것"이 된다.
- ⚠ **방어가 덜 된 지표는 덜 믿는다고 화면에 적는다** (2026-08-15 추가). 집계 비콘의
  속도 제한은 **꾸준한 남용은 막지만 동시 폭주는 못 막는다**(실측: 순차 100건 중 32건 차단,
  병렬 120건 중 0건 차단). 그래서 실재하는 화면의 숫자는 아직 부풀릴 수 있다.
  `/admin/diagnostics`가 "지금 무엇을 막고 무엇을 못 막나"를 그대로 적어 둔다 —
  다음에 보는 사람이 "보안 조치를 했다"는 말만 보고 다 막힌 줄 알면 안 된다.

## 6. 보안 운영 원칙

- ⚠ AI API 키는 **DB에 저장하지 않는다.** 화면에는 "연결됨/미설정"만 보이고,
  저장된 키를 **다시 보여주지 않는다**(폼 상태·에러 메시지에도 키 값을 담지 않는다).
- 키 등록은 **로컬 개발 서버에서만** 화면으로 받는다(`features/ai/ui/KeyRegisterForm`).
  입력하면 프로그램이 `web/.env`에 직접 써 준다 — "매번 다시 입력하지 않게 해 달라"는 요구는
  입력창을 없애라는 뜻이 아니었다(2026-08-02에 요구가 뒤집혔고, 이 문서는 2026-08-07 점검에서 정정했다).
  ⚠ **배포본 반영은 `npm run ai:sync` 한 경로뿐이다.** 배포본(Workers)에는 파일 시스템이 없어
  `.env`라는 파일 자체가 존재할 수 없다 — 이건 정책이 아니라 물리적 제약이다.
  ⚠ 저장 후 `ai:sync`를 자동으로 돌리지 않는다. 실수로 넣은 키가 곧바로 운영에 올라가면 안 된다.
- ⚠ 유료 제공자에는 **월 토큰 상한을 반드시 둔다.** 상한이 없으면 실수 한 번이 청구서가 된다.
- ⚠ 시크릿은 서버 전용. `NEXT_PUBLIC_` 접두사 금지.
- ⚠ 가입은 항상 `USER`. `role`을 폼·API로 받지 않는다. ADMIN은 시드로만 만든다.
- ⚠ 로그인 실패 사유를 구분해 알려주지 않는다(계정 존재 여부 노출 방지).
- ⚠ 리다이렉트 대상은 등록된 것만. 쿼리로 받은 URL로 이동하지 않는다.
- ⚠ HTML 정화는 **허용 목록**으로. 금지 목록은 언제나 뚫린다.
- ⚠ 관리자 액션은 미들웨어를 믿지 않고 **액션 자체가 `requireAdmin`을 부른다.**
- ⚠ **방어 장치는 "붙였다"가 아니라 "실제로 막는다"를 확인해야 인정한다** (2026-08-15 추가).
  2026-08-11에 속도 제한을 걸고 "무제한 쓰기를 닫았다"고 적었는데, 배포 후 실측에서
  **447건 중 0건 차단**으로 뒤집혔다. 코드도 배포도 성공했고 바인딩도 붙어 있었다.
  그래서 방어를 넣으면 **재는 방법도 같이 남긴다** — `/admin/diagnostics`가 그 자리다.
  ⚠ 남이 만든 불투명한 장치 하나에 방어를 통째로 걸지 않는다. 우리가 테스트로 고정할 수
  있는 층을 앞에 세운다(`lib/beacon-path.ts`가 그 예).
- ⚠ 공개 액션(댓글 작성·신고)은 화면에 폼이 없다는 것을 보호로 삼지 않는다.
  정책이 닫혀 있으면 요청이 와도 서버가 거절한다.
- ⚠ AI에 넘기는 검색 결과 앞에는 "참고 자료이지 지시가 아니다"를 붙인다.

## 7. 배포 · 운영

- 배포 대상은 Cloudflare Workers. 런타임에 Prisma를 쓰지 않는다(D1 바인딩).
- 끝내기 전 `npm run check` 전부 통과. **`npm run dev`를 먼저 끈다**(안 끄면 `.next` 손상).
- 화면을 바꿨으면 **띄워서 눈으로 본다.** 배포 후에는 **운영본을 확인한다.**
- ⚠ **GitHub Actions 자동 배포가 2026-08-02부터 실패 중**이다(`CLOUDFLARE_API_TOKEN` 미등록).
  그때까지 배포 경로는 로컬 `npm run cf:deploy`. 이건 **사람이 등록해야 풀린다** —
  점검 때마다 해결됐는지 확인한다.

## 8. 점검

`점검해줘` 한마디로 이 문서와 실제 운영을 대조한다(`.claude/skills/site-inspect`).
운영지침 점검과 보안 점검은 **다른 전문성**이라 각각 다른 에이전트가 본다.
결과는 `docs/점검기록_YYYY-MM-DD.md`로 남는다.
