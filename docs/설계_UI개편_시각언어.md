# 시각 언어를 하나로 묶고, 오래 봐도 피로하지 않게

> 목표는 **기능 추가가 아니라 시각 언어 통일과 톤 완화**다.
> 지금 화면은 다크(#0f1117) + 금색 포인트이고, 제안된 언어는 **크림(#f4f1e8) + 숲 녹색(#0b6640)
> + 테라코타(#b8672f)** 다. 색만 바꾸는 일이 아니라 **사이트의 인상을 바꾸는 일**이다.

---

## 1. ⚠ 먼저 — 프롬프트가 전제한 앱과 실제 앱이 다르다

프롬프트는 다른 구조를 가정하고 쓰였다. **그대로 실행하면 없는 파일을 만들고 있는 것을 못 고친다.**
아래 대조표가 이번 작업의 실제 범위다.

| 프롬프트의 전제 | 이 저장소의 실제 | 이번 작업에서 |
|---|---|---|
| React 6메뉴 · **사이드바 6메뉴** | Next.js App Router. **공개 화면은 상단 내비**(6개), 사이드바는 **관리자 전용**(16개) | 규칙은 상단 내비·관리자 사이드바 **양쪽에** 옮긴다 |
| `src/styles/tokens.css` 신설 | 토큰은 이미 한 곳에 있다 — **Tailwind v4 `@theme`**(`src/app/globals.css`) | 파일을 새로 만들지 않고 **거기에 두 벌(라이트/다크)로** 정의한다 |
| Recharts | **자체 SVG**(`CapitalFlowChart` · `Donut` · `StatBar`) | 격자·축·선 굵기 규칙은 그대로 적용 가능 |
| TradingView 위젯 `overrides` | 사이트에 **붙어 있지 않다**(저장소 루트에 프로토타입 html만) | ⚠ **해당 없음.** 나중에 붙일 때 규칙만 문서로 남긴다 |
| CANSLIM 분석 도구 | CANSLIM은 종목 보고서 채점에 쓰지만, 사이트의 1순위는 **티스토리 유입 콘텐츠** | 색·톤이 CTA 대비를 깎지 않는지 본다 |
| 다크모드 "추가" | 지금이 **다크 전용**이다 | ⚠ 방향이 반대다 — 아래 §2 결정 필요 |

⚠ **없는 것을 만들었다고 적지 않는다.** TradingView 항목은 수용 기준에서 빼고, "아직 없다"로 남긴다.

## 2. ⚠ 사람이 정할 것 (임의로 정하지 않는다)

프롬프트 자신이 *"판단이 갈리는 지점은 임의로 정하지 말고 물어보세요"* 라고 적고 있다.

### 2-1. 등락 색 — 한국식 vs 미국식 ⭐

프롬프트 토큰: `--up: #d0342c`(적색 상승) · `--down: #1f63c4`(청색 하락) — **한국 관행**.
지금 사이트: **미국식**(상승 emerald 녹색 · 하락 적색). `formatPct`가 쓰이는 모든 화면이 그렇다.

⚠ 이 사이트는 **한·미 종목을 함께** 다루고, 독자도 한국인이다. 어느 쪽이든 **한 번 정하면
전 화면이 따라야** 하고, 바꾸면 과거 스크린샷·블로그 이미지와 어긋난다.

공통으로 지킬 것(어느 쪽을 택하든): **색 단독으로 표시하지 않는다.** 부호(+/−)나 화살표를 함께 쓴다.

### 2-2. 기본 테마 — 크림 라이트로 전환할 것인가

프롬프트는 **라이트가 기본**이고 다크가 토글이다. 지금은 다크 전용이다.

| 안 | 뜻 | 비용 |
|---|---|---|
| 라이트 기본 + 다크 토글 | 프롬프트 그대로. 사이트 인상이 완전히 바뀐다 | 전 화면 재도색 + 두 모드 검수 |
| 다크 유지 + 라이트 추가 | 지금 인상을 지키고 선택지를 준다 | 같은 작업량 + 다크 팔레트도 새 토큰으로 |
| 다크만 새 팔레트로 | 금색 → 숲 녹색·테라코타. 가장 작다 | 라이트 검수 없음 |

⚠ 애드센스가 막 승인됐다. **광고는 대개 흰 배경**이라 크림 라이트에서 덜 튄다 — 라이트 전환은
광고 이질감을 줄이는 쪽이다. 반대로 지금의 다크+금색은 이 사이트의 인상 그 자체다.

### 2-3. 워드마크 A~D

프롬프트는 **둥근 모서리(B 계열)** 채택을 명시했고, 비교 이미지도 A(현행 각짐)·B(둥근 모서리)·
C(곡선 수관)·D(실루엣+여백 컷)를 나란히 둔다. ⚠ 최소 20px·**사이드바 24px에서 판독**이 조건이다.

## 3. '부드럽게'의 규칙 (그대로 채택)

감각이 아니라 규칙으로 다룬다 — 이 여섯이 전부다.

1. **순색 금지** — `#000`·`#fff`를 쓰지 않는다.
2. **모서리** — 카드 12px · 입력/버튼 8px · 이미지 12px · 태그 999px.
3. **그림자는 잉크 계열로** — 검정 그림자는 크림 위에서 때처럼 보인다.
4. **경계선보다 면 분리** — 1px 선 남발 금지, 배경 명도 차로 나눈다.
5. **모션** — 160ms `cubic-bezier(.2,.8,.2,1)`. ⚠ `prefers-reduced-motion: reduce`면 **0ms**.
6. **여백** — 4px 배수, 카드 패딩 최소 20px.

## 4. 단계 (하나씩, 각 단계가 배포 가능하게)

| # | 무엇 | 공수(세션) |
|---|---|---|
| U1 | **토큰 정비** — `globals.css @theme`에 라이트/다크 두 벌, Tailwind 색을 토큰에 연결 | 1.0 |
| U2 | **`Wordmark` 컴포넌트** — `currentColor` 기반, 크기 prop, 24px 판독 확인, 파비콘 두 벌 | 0.5 |
| U3 | **공개 화면 재도색** — 홈 블록 6 + `/macro` `/insights` `/portfolio` `/stocks` `/journal` 등 12화면 | 1.5 |
| U4 | **관리자 재도색** — 16화면 | 1.0 |
| U5 | **테마 토글** — 기본은 시스템, 선택은 `localStorage` | 0.5 |
| U6 | **하드코딩 hex 제거** — 지금 `.tsx`에 **103건**. ⚠ 대표 포트폴리오 버킷 색은 **DB 값**이라 별도 처리 | 0.5 |
| U7 | **검증·문서** — 라이트/다크 스크린샷, 대비, reduced-motion, `docs/woodsman_design_system.md` | 1.0 |
| | **합계** | **6.0** |

⚠ U6의 **DB에 저장된 색**(`PortfolioBucket.color`)은 토큰으로 덮을 수 없다. 관리자가 고르는 값이라
**팔레트를 골라 주는 UI**로 풀어야 한다(임의 hex 입력을 막는 것은 이미 검증이 있다).
