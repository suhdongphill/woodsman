## 0-2. ⭐ 다음에 할 것 — 미시간 소비심리 (2026-08-25 결정됨)

**결정: 예외를 주되(105일) 그 사실을 `read` 문구로 독자에게 알린다.**

### 왜 이 안인가

미시간대는 매월 발표하는데 **FRED 반영이 두 달 늦다.** 그래서 FRED만 보는 우리 수집
경로에서는 오늘 최신이 언제나 두 달 전 값이다(현재 `2026-06-01`). 기본 월간 기한 75일을
넘겨 **「기한초과」가 영원히 켜져 있다** — 그런데 더 새 값이 존재하지 않는다.

⚠ 확인해 둔 사실 하나가 판단을 갈랐다 — **`staleWhy`는 코드에만 있고 화면에 안 나온다.**
독자가 보는 것은 이유 없는 회색 딱지뿐이다.

| 안 | 문제 |
|---|---|
| 그냥 두기(사이트 현행) | 영원히 켜진 경고 → 회색이 무의미해지고, **진짜 낡은 지표가 같은 색에 묻힌다** |
| 예외만 주기(볼트 현행) | 독자가 두 달 전 값을 오늘 값으로 읽는다 |
| **채택** | 딱지를 지우는 게 아니라 **딱지가 하던 말을 글로 옮긴다** |

`freshness.ts` §1-7의 *"오탐 한 건이 미탐 열 건보다 비싸다"* 가 겨냥한 자리다.

### 할 일

1. `lib/macro/sectors/consumer.ts`의 `umcsent`에 `staleDays: 105` + `staleWhy` 추가
   - 근거 문장은 볼트 `_scripts/sectors/macro.json`의 것과 **같게** 쓴다(두 화면 대조용)
2. 같은 지표의 `read`에 **지연 사실을 한 줄** 넣는다 —
   대략: *"⚠ 이 숫자는 미시간대 원발표가 아니라 FRED에 반영된 값이라 **구조적으로 두 달 뒤집니다.**
   오늘 값이 아니라 두 달 전 조사 결과로 읽으세요."*
3. 그러면 볼트와 값도 같아진다 → `docs`의 대조표에서 미시간 줄의 ⚠를 뗀다

⚠ **네 번째 선택지는 남겨 둔다.** 미시간대 원발표를 직접 받는 수집 경로를 만들면 딜레마
자체가 사라진다. 다만 FRED가 아닌 소스라 어댑터가 하나 더 필요해서, 아래 EIA 원유재고와
같은 부류의 일이다. **급하지 않다 — 위 2단계로 독자에게는 이미 정직해진다.**

## ⚠ 매번 지킬 것

- `npm run dev`를 **끄고** `npm run check` — **build 뒤에 dev를 띄울 때도** `.next`를 지운다
- ⚠ **dev를 껐는지 실제로 확인한다.** Windows에서 `pkill -f`는 node 프로세스를 **못 잡는다** —
  2026-08-25에 살아남은 dev 서버 두 개가 `.open-next`를 잡고 있어 배포가 `EPERM`으로 죽었다.
  `Get-CimInstance Win32_Process -Filter "Name='node.exe'"`로 세고, `Stop-Process -Force`로 끈다
- 화면을 바꿨으면 **실제로 띄워서 본다.** 값이 없으면 로컬 D1에 실데이터를 넣고서라도 본다(오늘 그렇게 했다)
- **모듈로 쪼갠다.** 판단은 `lib/*`(순수 함수 + 테스트), 질의는 `*-repo`, 액션은 `*-actions`, 화면은 `ui/*`
- **빈 칸을 0으로 만들지 않는다.** 없는 값을 채우면 없는 사실이 생긴다
- **화면이 하지 않는 일을 한다고 적지 않는다**
- **운영 데이터를 두드리는 실측은 먼저 묻는다**
- `web/CHANGELOG.md`에 **"왜"** 를 남긴다
- 배포 후 **운영본을 검증한다.** 로컬 통과가 배포 성공이 아니다
- 지시가 `docs/운영지침.md`와 어긋나면 **먼저 말하고**, 진행 여부는 사람이 정한다
