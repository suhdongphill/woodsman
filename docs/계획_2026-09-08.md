## 확인 2 — 「자동」 배지: 없다. ⚠ **계획에 적은 가설이 틀렸다**

계획은 「없으면 시크릿이 아니라 Cron Trigger 등록부터 본다」였다. 재 보니 반대였다.

| 무엇 | 어떻게 쟀나 | 결과 |
|---|---|---|
| Cron Trigger | Cloudflare API `/workers/scripts/woodsman/schedules` | ⭐ **등록돼 있다** — `0 21 * * *`, created 2026-09-05T11:43Z |
| 배포본 | `wrangler versions view b72dd7ba` | `Handlers: fetch, scheduled` · `Secret Name: CRON_SECRET` **둘 다 있다** |
| 수집 이력 | D1 `MacroIngest` 전량 | **CRON 행 0건.** 전부 MANUAL, 마지막 9/7 12:32 |
| 화면 | `/admin/macro` 자동 수집 카드 | **`시크릿: ⚠ 없습니다`** |

**등록은 됐는데 런타임이 값을 못 읽는다.** 그리고 CRON_SECRET 혼자가 아니다 —
`/admin/ai`도 「지금은 마스터 키로 **AUTH_SECRET**을 쓰고 있습니다」라고 말한다.
`KEY_ENCRYPTION_KEY`도 똑같이 안 읽힌다. **둘 다 9/5에 같이 넣은 시크릿**이고,
같은 함수(`readRuntimeEnvMany`)로 나란히 읽는 `AUTH_SECRET`은 읽힌다.

### ⚠ 바꾸기 전에 적는 가설

> 9/5에 `npx wrangler secret put CRON_SECRET`을 **대화형 프롬프트**로 넣었고
> (계획_2026-09-05.md §1), 그때 값이 들어가지 않아 **이름만 등록되고 값이 비었다.**
> 그래서 `readRuntimeEnv("CRON_SECRET")`이 빈 문자열을 돌려주고,
> `worker.js`의 `scheduled`가 첫 줄에서 되돌아 나가 `/api/cron`을 부른 적이 없다.

**맞으면 이렇게 된다** — 값을 다시 넣으면
① `/admin/macro`가 「시크릿: 등록됨」으로 바뀌고
② 그 값으로 `/api/cron`을 부르면 200과 함께 `MacroIngest`에 **CRON 행이 처음 생긴다.**

**틀리면** — 다시 넣어도 화면이 「없습니다」 그대로다. 그러면 문제는 값이 아니라
`getCloudflareContext().env`가 이 이름만 안 실어 주는 쪽이다.

⚠ **`KEY_ENCRYPTION_KEY`는 오늘 건드리지 않는다.** 지금 넣으면 마스터 키가
AUTH_SECRET 파생에서 바뀌어 **저장된 API 키 9개가 전부 못 풀린다.**
9개를 다시 등록할 준비를 하고 따로 한다.
