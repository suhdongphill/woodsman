### ⚠ 알게 된 것 1 — AdSense는 **애초에 안 돌고 있었다**

CSP를 두 벌로 나눈 가장 큰 이유가 "광고를 죽이지 않으려고"였는데,
`wrangler secret list`에 **`ADSENSE_CLIENT_ID`가 없다.** 즉 운영본은 광고 스크립트를
한 번도 부르지 않았다(`AdSense.tsx`가 clientId 없으면 `null`을 낸다).

- ⚠ **그래도 설계는 그대로 둔다.** 광고를 켜는 날 전역 CSP가 광고를 죽이면
  원인을 찾는 데 한참 걸린다. 지금 나눠 둔 것이 그때를 위한 것이다.
- ⚠ 다만 **"CSP가 광고를 안 죽인다"는 아직 실측된 적이 없다.** 광고를 켤 때 다시 재야 한다.

### ✅ 알게 된 것 2 — 점검의 낮음 1건이 해소됐다

`lib/auth.config.ts:37`의 `trustHost: true`가 위험한지는 **AUTH_URL이 실제로 있는지**에
달려 있었고, 점검기록에는 "⚠ 추측"으로 남아 있었다.
`wrangler secret list` 결과 **`AUTH_URL`·`SITE_URL`·`AUTH_SECRET` 셋 다 있다.** 위험 아님.

### ⚠ 아직 못 한 검증 — 사람이 해야 한다

**로그인이 되는지 확인하지 못했다.** `authorize()`를 건드렸는데,
확인하려면 로그인 폼에 비밀번호를 넣어야 해서 내가 할 수 없다.

```
1) 시크릿 창으로 https://portfolio-solutions.net/login
2) 정상 계정으로 로그인 → 들어가지는가          ← 가장 중요
3) 아무 없는 주소(예: test-lock@example.com)로 6번 틀리기
   → 5번째부터 막히는가, 1분 뒤 풀리는가
   ⚠ 본인 계정으로 하지 말 것 — 진짜로 잠긴다
```

로그는 `npx wrangler tail woodsman`으로 볼 수 있다 —
`[auth] 로그인 실패` / `[auth] 로그인 시도 제한으로 거절했다`가 찍혀야 한다.

## 4. 오늘 만든 것의 꼬리

### 4-1. ⚠ CSP는 아직 인라인 스크립트를 못 막는다

XSS의 실제 통로인 `<img onerror=>`를 막으려면 `script-src`에 nonce가 필요하고,
Next.js에서 nonce를 쓰면 **모든 페이지가 동적 렌더로 바뀐다**(요청 헤더를 읽어야 하므로).
공개 화면 전체의 정적 최적화를 포기하는 값이라 걸지 않았다.

지금 서 있는 층:

| 층 | 무엇을 막나 |
|---|---|
| 1 | `lib/sanitize-html.ts` 허용 목록 — 들어오는 문 |
| 2 | `looksDangerous()` 마지막 관문 — 1층이 뚫렸을 때 **글자만 남기고 로그를 남긴다** |
| 3 | CSP `base-uri`·`object-src`·`form-action`·`frame-ancestors` — 뚫린 뒤의 **활용**을 막는다 |
| — | ❌ 인라인 실행 자체 |

### 4-2. ✅ 정했다 — **발행 시점 이름을 얼린다**

8/17부터 미뤄 둔 판단이다. **보고서는 기록이다** — 발행 당시 "성장 버킷이라 산다"고 썼으면
나중에 분류 이름을 바꿔도 그때의 판단이 그대로 남는다.
`StockReportContext.functionName`에 발행 시점 이름을 함께 얼리고,
이름을 내는 자리를 `holdingFunctionLabel()` 하나로 모았다.
⭐ 발행본이 0건일 때 정해서 옛 스냅숏을 메울 일이 없었다.

### 4-3. C7 시세 자동 갱신(Cron) 미구현

Cloudflare Cron Trigger 하루 1회(장 마감 후). 지금은 버튼을 눌러야 받는다.
⚠ 실패 시 `console.error`를 남기고 **직전 값을 유지**한다(조용한 실패 금지).
⚠ 다만 **버튼조차 운영에서 한 번도 안 눌렸다.** 손으로 한 번 돌려 보는 게 먼저다(§2-5).
