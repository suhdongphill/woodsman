# WoodsMan 디자인 시스템 — 화면

> 원칙 하나로 요약하면: **오래 들여다봐도 피로하지 않게.**
> 그래서 순색을 쓰지 않고, 모서리를 둥글리고, 선보다 면으로 나눈다.

---

## 1. 값은 한 곳에만

모든 색은 `web/src/app/globals.css`의 `--w-*` 변수다. **컴포넌트에 hex를 쓰지 않는다.**

```
grep -rn "#[0-9a-fA-F]\{3,8\}" --include=*.tsx src
```

2026-08-30 기준 **1건**만 남는다 — `BucketManager`의 색 선택기 기본값이다.
`<input type="color">`는 리터럴 hex만 받으므로 물리적으로 토큰을 쓸 수 없다.
(구글·카카오 로그인 버튼의 브랜드색은 규격이라 예외로 둔다.)

### ⚠ Tailwind와 잇는 법

`@theme inline`으로 잇는다. **`inline`이 빠지면 빌드 때 값이 박혀 테마 토글이 안 먹는다** —
화면은 멀쩡해 보이고 토글만 조용히 죽으므로 알아채기 어렵다.

### ⚠ SVG에서는 `style`로 준다

`fill=`·`stroke=` **속성은 `var()`를 읽지 못한다.** 속성에 넣으면 색이 사라져 검게 칠해진다.

```tsx
<path style={{ fill: "var(--w-series-1)" }} />   // ✅
<path fill="var(--w-series-1)" />                // ❌ 조용히 검게 칠해진다
```

다시 재고 FAIL이 없어야 한다.

### ⚠ 등락 — 한국식이다

**상승 적색 · 하락 청색.** 미국과 반대다(2026-08-30 결정).

- 판단은 `lib/format.ts`의 **`profitColor()` 한 곳**에서만 한다. 화면에서 다시 정하지 않는다.
- ⚠ **색 단독으로 표시하지 않는다.** `formatPct`가 부호(+/−)를 함께 낸다 —
  색맹 사용자와 흑백 인쇄를 위해서다.
- ⚠ `text-emerald-*`를 등락에 쓰지 않는다. 녹색은 **성공·발행**의 색이다.
  (이름이 색을 배신하면 다음 사람이 반드시 틀린다.)

## 3. 형태

| 항목 | 값 | 왜 |
|---|---|---|
| 카드 모서리 | 12px | 인쇄물용 4px는 화면에서 딱딱하다 |
| 입력·버튼 | 8px | |
| 태그·필터 | 999px | |
| 카드 패딩 | 최소 20px | 밀도를 높이고 싶은 유혹을 참는다 |
| 그림자 | `--w-shadow-sm/md` (숲 잉크 기반) | ⚠ 검정 그림자는 크림 위에서 **회색 때**처럼 보인다 |
| 전환 | 160ms `cubic-bezier(.2,.8,.2,1)` | |
| 여백 | 4px 배수 | |

⚠ **경계선보다 면 분리.** 1px 선을 남발하지 말고 배경 명도 차이로 나눈다.

⚠ **`prefers-reduced-motion: reduce`면 전부 0ms.** "거의 안 움직인다"가 아니라 0이다 —
어지럼증은 정도의 문제가 아니다.

## 4. 워드마크

`web/src/components/brand/Wordmark.tsx` 하나뿐이다. 침엽수 3단 + 테라코타 밑동 +
세리프 **WoodsMan** + 테라코타 **「나무꾼 이야기」**.

- 나무는 `currentColor` — 부모에서 색을 주면 라이트/다크가 자동으로 맞는다. **두 벌을 만들지 않는다.**
- ⚠ 둥근 모서리는 `stroke-linejoin="round"` + 같은 색 stroke가 만든다.
  **`strokeWidth` 2.6을 줄이면 각이 다시 살아난다.**
- 최소 20px. 그 아래에서는 글자를 떼고 나무만. **26px 축소 판독 확인 완료**(관리자 사이드바).
- 파비콘은 `public/woodsman-mark.svg`. ⚠ 파비콘은 문서 밖에서 그려져 **CSS 변수를 못 읽으므로**
  거기에만 값을 박는다. 모양을 바꾸면 두 파일을 같이 고친다.

## 5. 테마

세 상태다 — **시스템 · 밝게 · 어둡게**. 기본은 시스템, 선택은 `localStorage`.

⚠ 토글을 두 상태로 만들면 **시스템을 따르던 상태로 돌아갈 방법이 없어진다.**
한 번 고르면 영영 고른 채로 사는 화면은 설정이 아니라 함정이다.

⚠ `layout`의 **첫 페인트 스크립트**가 없으면 다크를 고른 사람이 흰 화면을 한 번 맞는다(FOUC).
판단은 `lib/theme.ts`(순수 함수 + 테스트), 실행만 layout에서 한다.

## 6. 컴포넌트 규칙

- **카드** — `bg-card` + 1px `border-border` + 12px + `shadow-sm`. 호버 시 `shadow-md`, 160ms.
  ⚠ 카드 안에 카드를 중첩하지 않는다. 안쪽은 `surface-2` 면으로 나눈다.
- **표** — 머리 행은 `surface-2`. **세로 구분선 없음.** 숫자 열은 우측 정렬 + `tabular-nums`.
- **차트** — 격자 `--w-border` 1px, 축 라벨 `--w-ink-3`, 선 2px.
  ⚠ **이중 축(y축 2개) 차트를 만들지 않는다.** 나누거나 공통 기준으로 지수화한다.
- **아이콘** — 1.5px stroke, 둥근 끝. 각진 세트를 쓰지 않는다.
- **이미지 위 글자** — 검정 오버레이 대신 숲 잉크 `rgba(30,58,43,.55)`.

## 8. 타이포그래피 · 가독성 (2026-09-17 추가)

⚠ 이 장은 **재고 나서** 썼다. 아래 숫자는 이 저장소의 토큰과 `globals.css`를 실제로 계산한 값이다.

### 8-1. 잰 것

**본문** — `.prose-woodsman p` 는 `0.9375rem`(**15px**) · 행간 1.85 · `max-w-3xl`(px-6 빼면 720px).
15px 한글은 한 줄에 약 **48자**가 들어간다. 한글 권장 줄길이는 35~45자다. **두 칸 넘친다.**

**대비**(WCAG · 본문 4.5 · 큰 글씨/그래픽 3.0) — 라이트 / 다크, 바탕(`--w-bg`) 위:

| 토큰 | 라이트 | 다크 | 판정 |
|---|---:|---:|---|
| `--w-ink` 본문 | 10.97 | 14.33 | ✅ |
| `--w-ink-2` 보조 | 4.99 | 8.25 | ✅ (단 `surface-2` 위 4.48 — 경계) |
| `--w-ink-3` 흐림·축 라벨 | **2.87** | 4.49 | ❌ 라이트는 **그래픽 기준 3.0도 미달** |
| `--w-series-2` 테라코타 | **3.70** | **3.69** | ❌ 본문 미달 — ⚠ **본문 링크·CTA 색이다** |
| `--w-danger` 위험·오류 | 6.27 | **4.24** | ❌ 다크에서 본문 미달 — ⚠ **오류 메시지다** |
| `--w-up` 상승 | 4.42 | 4.77 | 🟡 라이트 경계 (부호가 함께 나와 치명적이진 않다) |

⚠ 셋이 문제이고, **둘은 그냥 미관이 아니다.**
테라코타는 [티스토리 CTA의 색](../web/CLAUDE.md)이라 **1순위 목적이 걸려 있고**,
다크의 `danger`는 **반드시 읽혀야 하는 글자**다.

### 8-2. 본문 척도 (표준)

기준은 **KRDS**(대한민국 정부 디지털 서비스 스타일 가이드)의 본문 17px이다.
iOS 기본 17pt · Android 16dp와도 같은 자리다.

| 역할 | 크기 | 굵기 | 행간 | 색 |
|---|---:|---:|---:|---|
| 글 제목 | 28px | 700 | 1.35 | `--w-ink` |
| 절 제목 (h2) | 21px | 700 | 1.4 | `--w-ink` |
| 소제목 (h3) | 18px | 600 | 1.5 | `--w-ink` |
| **본문** | **17px** | 400 | **1.85** | `--w-ink` |
| 목록 | 17px | 400 | 1.8 | `--w-ink` |
| 캡션·출처·기준일 | 14px | 400 | 1.6 | `--w-ink-2` |
| 숫자(표·지표) | 17px | 500 | 1.5 | `tabular-nums` · 우측 정렬 |

⚠ **행간 1.85는 KRDS(150%)보다 넓다. 의도한 것이다.**
KRDS의 150%는 버튼·목록까지 포함한 UI 기준이고, 우리 화면은 **거시 분석을 오래 읽는 곳**이다.
한글은 라틴 문자와 달리 글자마다 위아래 삐침이 없어 줄이 붙어 보인다 — 장문에서는 1.7~1.9가 편하다.
**이것이 Woodsman이 KRDS와 다르게 가는 자리다. 줄이지 않는다.**

⚠ **본문을 17px로 올리면 줄길이가 저절로 맞는다.** 720px ÷ 17px ≈ **42자** — 권장 범위 안이다.
`max-w-3xl`을 건드릴 필요가 없다. 한 값을 고쳐 두 문제가 풀린다.

### 8-3. 고칠 것 셋 (대비)

1. **`--w-ink-3` 라이트** `#8a9188` → 더 어둡게. 축 라벨이 안 보인다.
2. **테라코타 본문 링크** — 포인트색은 그대로 두되, **글자에 쓰는 변형**을 따로 만든다
   (`--w-accent-text`). ⚠ 브랜드색을 바꾸는 게 아니라 **글자용 한 칸 더 진한 값**을 더하는 것이다.
3. **`--w-danger` 다크** `#d1554d` → 밝게. 오류가 안 읽히면 그건 오류가 아니라 침묵이다.

⚠ **색만으로 뜻을 전하지 않는다**(기존 §2 규칙 유지). 부호·아이콘·글자를 함께 낸다.

### 8-4. Woodsman 고유 표기 — 이게 우리 독창성이다

우리 글에는 남이 안 쓰는 **근거 등급 표기**가 있다. 지금은 맨 글자로 붙어 있어 그냥 묻힌다.
**이것을 타이포로 세우면 사이트와 티스토리 양쪽에서 「Woodsman 글」임이 한눈에 보인다.**

| 표기 | 뜻 | 모양 |
|---|---|---|
| `사실` | 1차 자료로 확인 | 숲(`--w-series-1`) 테두리 배지 · 13px · 600 |
| `해석` | 사실에서 끌어낸 읽기 | 슬레이트(`--w-series-3`) 배지 |
| `가설` | 아직 실현되지 않음 | 테라코타(`--w-accent-text`) 배지 |
| `미확인` | 확인하지 못함 | `--w-ink-3` 점선 테두리 배지 |
| `⚠` | 되돌리면 안 되는 것 · 주의 | 본문 그대로. 색을 주지 않는다 |

⚠ **배지는 문장 앞에 붙고 줄을 바꾸지 않는다.** 읽는 흐름을 끊으면 글이 표가 된다.

### 8-5. 티스토리에도 같은 표준

티스토리에는 우리 CSS가 가지 않는다. 그래서 **글 안에서 닫히는 방법**만 쓴다.

- 티스토리 스킨 편집 → CSS에 §8-2 척도와 토큰을 **한 번** 심는다. 그다음부터 글은 그냥 쓴다.
- 스킨을 못 고치는 상황이면 배지만 인라인 `style`로 넣는다. ⚠ 본문 전체에 인라인을 뿌리지 않는다 — 고칠 수 없게 된다.
- ⚠ 티스토리 본문 폭은 스킨이 정한다. **글자 크기를 우리가 17px로 맞추면 줄길이는 따라온다.**

### 8-6. 점진적으로 — 한 번에 하나씩

⚠ 한꺼번에 올리면 **무엇이 읽기를 좋게 했는지 영원히 모른다**(운영지침 §3-1).

| 순서 | 무엇 | 가설 (배포 전에 적는다) |
|---|---|---|
| T1 | 본문 15px → 17px (+ h2 21px · h3 18px) | 글 페이지 이탈률이 내려가고 **티스토리 CTA 클릭이 는다** — 끝까지 읽어야 CTA를 본다 |
| T2 | 대비 셋 수정 (`ink-3` · `accent-text` · 다크 `danger`) | 눈에 띄는 변화는 없다. **재는 것은 대비값이지 클릭이 아니다** |
| T3 | 근거 등급 배지 | 글의 인상이 달라진다. 티스토리 유입에는 중립 |
| T4 | 티스토리 스킨 CSS 일치 | 두 곳의 글이 같은 글로 보인다 |

⚠ T1과 T2를 묶지 않는다. T1은 클릭으로 재고, T2는 클릭으로 재지지 않는다 — **재는 자가 다르면 배포를 나눈다.**
