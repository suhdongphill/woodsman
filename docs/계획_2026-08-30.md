## 1. ⭐ 오늘 밝혀진 것 — 배포 문제의 진짜 원인

### ⚠ 전제 1이 틀렸다 — GitHub Secret은 **이미 등록돼 있다**

계획 1-10은 네 세션째 *"`gh secret set CLOUDFLARE_API_TOKEN`·`CLOUDFLARE_ACCOUNT_ID` — 8/2부터 미완"*
으로 적혀 있었다. **아니었다.** 둘 다 2026-08-06에 등록돼 있다(`gh secret list`).

그런데 자동배포는 **2026-08-06 이후 12회 연속 실패**했고, 실패 지점이 늘 같다.

```
D1 마이그레이션 적용 → npx wrangler d1 migrations apply woodsman-db --remote
✘ [ERROR] In a non-interactive environment, it's necessary to set
          a CLOUDFLARE_API_TOKEN environment variable for wrangler to work.
```

워크플로는 `apiToken:`을 제대로 넘기고 있다(`.github/workflows/deploy.yml:65`).
러너에서 비어 보인다는 것은 **등록된 토큰 값 자체가 비었거나 잘못됐다**는 뜻이다.

⭐ **그래서 할 일이 바뀐다.** "등록하기"가 아니라 **"다시 넣기"** 다 —
`gh secret set CLOUDFLARE_API_TOKEN`. 값은 사람만 가지고 있다.

⚠ 이 오진단 때문에 세 세션 동안 1순위 목록에 **엉뚱한 항목**이 올라 있었다.
설계서 §7에 증상·원인·오진단을 그대로 남겼다 — 다음에 또 같은 착각을 하지 않도록.

### ⚠ 전제 2 — 로컬 커밋이 GitHub에 안 밀려 있다

`origin/main`은 아직 `285b872`(8/16)다. **로컬이 16커밋 앞선다.**
8/16 이후 워크플로 실행 기록이 없는 건 트리거가 고장 난 게 아니라 **push가 없었기 때문**이다.

⚠ **push는 하지 않았다.** 지금 밀면 CI가 또 실패한다. **토큰을 다시 넣은 뒤에 미는 것이 맞다.**
