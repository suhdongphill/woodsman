# 종목분석 보고서 설계서 v1

> 포트폴리오를 **관리하는** 프로그램이므로, 종목 보고서는 읽을거리가 아니라
> **비중 판단에 실제로 쓰이는 도구**여야 한다. 목표는 "증권사 애널리스트 수준의 리포트를
> 사이트가 생산한다"이다.
>
> 이 문서는 한 번 쓰고 마는 명세가 아니라 **계속 고쳐 쓰는 설계서**다.
> 새 보고서를 발행할 때마다 좋았던 장치를 여기로 올린다.

## 1. 지금 화면의 진단

`/stocks/[ticker]`는 보고서가 아니다. 형식이 없는 것보다 나쁜 문제가 둘 있다.

| 문제 | 지금 | 왜 나쁜가 |
|---|---|---|
| ⚠ 결측을 0점 | `scores[key] ?? 0` | 버블 점수에서 "안 본 것을 괜찮은 것으로 만들지 않는다"고 정해 둔 규칙의 정반대. 정책도 `N/A`는 산출에서 빼라고 한다 |
| ⚠ 등급 경계 불일치 | 7.0/5.0 | 정책은 **8.0/6.5**. 화면이 정책보다 후하게 판정한다 |
| 점수의 출처 없음 | `CANSLIM_SCORES = {TSM, NVDA, DEFAULT}` 하드코딩 | 근거·출처·기준일이 없는 점수는 숫자 모양의 의견이다 |
| 종목·차트 목업 | `lib/mock` · `mockSeries` | 남은 마지막 목업(계획서 C단계) |

빠진 것은 더 크다 — **투자 논지·산업 분석·경쟁 구도·시나리오·비중 조절 프레임·미확정 체크리스트가
통째로 없다.** 지금 화면으로는 "이 종목을 얼마나 담을지"를 판단할 수 없다.

## 2. 원본 3건에서 가져올 장점

`_published`의 실제 발행본 3건은 성격이 다르고, **셋을 합쳐야 하나의 완성형**이 된다.

### A. 한국콜마 (티스토리용 HTML) — *산업 사이클 리서치형*

가장 완성도 높은 서사 구조. 여기서 가져올 것:

1. **9섹션 서사** — Summary → 산업 → 기업 → 경쟁 → 수급 → 지속성 → 시나리오 → 비중 → 체크리스트.
   결론이 맨 앞에 오고, 뒤로 갈수록 근거가 두꺼워진다.
2. ⭐ **미조회 고지 + 빈 프레임 + 조회처** (§05) — "본 작성 환경에서 KRX 접속이 차단되어
   수치를 확보하지 못했다. **원칙에 따라 추정치를 기입하지 않으며**" + 빈 표(`—`) + 어디서 구하는지.
   **이 설계서 전체에서 가장 중요한 장치다.** 모르는 것을 모른다고 쓰면서도 화면이 비어 보이지 않는다.
3. ⭐ **판정에 철회 조건을 붙인다** (§06) — "수출 ΔYoY가 2개월 연속 마이너스로 꺾이는 순간이
   이 판정의 **공식 철회 조건**이다." 반증 조건 없는 판정은 판정이 아니라 소감이다.
4. **1차 미분(ΔYoY) 사고** — 레벨이 아니라 **기울기**를 본다. "성장률의 1차 미분까지 양(+)으로 재점화".
   버블 모니터의 `capex_accel`(2차 미분)과 같은 계열의 사고다.
5. **목표주가를 내지 않고 판정 기준 문장을 남긴다** (§07) — "PER 확인 후 이 문장 하나로 판정하면 된다."
6. **조건-대응 매트릭스** (§08) — 확대 근거 ①~④ / 유지 / 축소 트리거 ①~⑤.
   **손절 규율(−7~10% 기계 집행)**까지 숫자로. "의사결정 대행이 아니라 조건-대응"이라고 못 박는다.
7. **미확정 항목 체크리스트** (§09) — `항목 · 소스 · 영향`. 그대로 **다음 갱신의 작업 목록**이 된다.
8. **월 단위로 검증 가능한 지표를 고른다** — "매월 1일 전후 산업부 수출입동향의 화장품 항목 하나가
   사실상의 월간 성적표". 검증 주기가 짧은 지표를 논지의 축으로 삼는다.
9. **외부 통계를 프록시로** — 산업 수출 성장률을 ODM 매출 성장률의 **하한 프록시**로 사용.
10. **근사치 표기 규율** — `~2.45조원` + "작성 시점 확정 공시분의 근사치, DART 원문 대조 요망".

### B. LG이노텍 (CANSLIM 과제분석) — *보유 종목 대응형*

이미 들고 있는 종목을 **오늘 어떻게 할 것인가**에 답한다. 가져올 것:

1. **히어로 KPI 4종** — 현재가 · 당일 등락 · 52주 범위 · 시가총액. 위치를 한눈에.
2. **속보 박스** — "오늘 무슨 일이 있었나" + 급등 이유 ①② + **거래량 배수**(일평균 대비 10배 이상).
   보고서에 시간축을 넣는 장치.
3. ⭐ **Envelope(20주MA ±20%) 밴드 + 시나리오별 대응 표** — 🟢신규매수 / 🟡보유 중 / 🔴손절을
   **구체적 가격대**와 함께. 판단이 아니라 **대응 규칙**을 준다.
4. **거래대금 임계 체크** — 분기 거래대금 2조원 돌파 여부로 유동성 국면 판정. 역대 최대 분기와 비교.
5. ⭐ **해자(Moat) + 병목(Bottleneck) 5단 분석** — ①기술 ②전환비용 ③신사업 ④**약점** ⑤병목.
   해자의 깊이를 **경쟁사 탈락의 역사**로 증명한다(오필름 인권 이슈 퇴출, 샤프 신뢰 상실 → 개발과제 미참여).
   주장이 아니라 사례로 해자를 재는 방식.
6. **한 줄 압축 판정** — "단일 성(城) 위의 깊은 해자 — 강력하지만 편중된 구조", "깊지만 좁음".
7. **종목 고유 계절성 표** — Q1~Q2 분할매수 / Q3 보유 / Q4 차익실현. 그리고
   "지금은 **비계절적** 급등이므로 추격보다 조정 대기"처럼 계절성에서 벗어난 국면을 따로 판정.
8. **변동성 이벤트 로그** — `시점 · 변동 · 원인` 표. "한 번의 이슈로 반토막, 한 번의 모멘텀으로 3배"를
   숫자로 증명한다.
9. ⭐ **시계(horizon) 분리** — 중장기(6~12개월) 구조적 상승 ✅ / 단기(1~3개월) 과열 조정 ⚠.
   두 판정이 모순돼 보이지 않게 **기간을 먼저 밝힌다.**
10. **최종 종합 판단 표** — 항목(해자·병목·Envelope·변동성·방향성)마다 한 줄 평가.

### C. 두산에너빌리티 (PBR 밸류에이션 docx) — *정량 밸류에이션형*

숫자로 결론까지 가는 유일한 문서. 가져올 것:

1. **피어그룹 병렬 비교** — 3사를 같은 표에 놓고 상대 평가. 단독 평가는 기준이 없다.
2. **계산 과정을 노출** — 지배주주자본 ÷ 발행주식수 = BPS → 현재 PBR. 독자가 검산할 수 있다.
3. ⭐ **이론값과 현실의 괴리를 숫자로** — 적정PBR = ROE ÷ COE. "ROE 0.7% / COE 8.5% →
   **이론 적정 PBR 0.08배**(현재 9.1배)". 괴리 자체가 메시지다.
4. **역사적 멀티플 밴드 + ROE 병기** — 3년 저점·고점과 ROE를 나란히. 멀티플이 정당화되는지 판정.
5. **목표 멀티플 산정 근거를 문장으로** — "피어 평균 4.75배 × ROE 열위 할인 −37% = 3.0배".
6. ⭐ **목표주가 합리성 교차검증 표** — 목표 / 피어평균 / 역사평균 / ROE개선 가정 / 증권사 컨센서스
   **5가지로 같은 질문을 다시 묻는다.** 한 숫자를 다섯 각도에서 때려 본다.
7. ⭐⭐ **방법론 자체의 한계를 명시** — "PBR은 수주 모멘텀 기업에 본질적 한계가 있다.
   증권사는 EV/EBITDA를 쓰므로 괴리가 난다." **자기 방법론을 스스로 부정할 줄 아는 것**이
   이 문서의 가장 강한 대목이다. 신뢰는 결론이 아니라 한계 고백에서 나온다.
8. **Bull Case / Bear Case 대칭 배치** — 개수까지 맞춘다.
9. **수치 출처를 항목별로** — "지배주주자본 77,857억원: 2026.03.22 감사보고서 **확정치** /
   BPS: 키움증권 리서치(2025.02) / ROE: 공개 리서치 **추정치**". 확정과 추정을 문장에서 구분.
10. **다음 판단 시점을 날짜로** — "1Q26 실적(2026년 4월 30일) 발표에서 확인된 후 접근".

## 4. 코드로 강제할 정직성 규율 7가지

형식은 베낄 수 있지만 **규율은 코드가 강제해야 유지된다.** 순수 모듈과 테스트로 못 박는다.

| # | 규율 | 강제 방법 |
|---|---|---|
| R1 | **결측은 분모에서 뺀다.** N/A는 0점이 아니다 | `lib/canslim/score.ts` — 버블 `score.ts`와 같은 방식. 테스트로 고정 |
| R2 | **모르면 비워 두고 조회처를 적는다.** 추정치로 칸을 채우지 않는다 | 빈 필드는 `—` + `조회처` 필수. 조회처 없이 빈칸이면 검증 오류 |
| R3 | **판정에는 철회 조건이 붙는다** | 구조 판정 필드에 `revokeIf` 필수. 없으면 발행 불가 |
| R4 | **목표주가를 내지 않는다** | ⚠ **열린 결정 §8-①** — 현행 `WOODSMAN_DOCTRINE`과 두산 보고서가 충돌한다 |
| R5 | **확정과 추정을 문장에서 구분한다** | 모든 수치에 `confirmed`/`needsCheck`/`na` 태그. 태그 없는 수치는 저장 거부 |
| R6 | **방법론의 한계를 같이 쓴다** | §07 밸류에이션에 `limitation` 필수 |
| R7 | **다음 판단 시점을 날짜로 남긴다** | `nextCheckAt` + 체크리스트 §11 |

| **AI 초안** | §01 논지 · §05 해자 · §06 경쟁 구도 · §09 시나리오 | `lib/ai` (아래 §6) |
| **사람 확정** | 모든 수치의 태그 · §10 트리거 · §11 체크리스트 | 관리자 화면 |
| **미조회** | 외국인·기관 수급 (§08) | ⚠ 빈 프레임 + 조회처 유지 |

### 5-2. ⚠ 미장·국장은 데이터 소스를 나눈다 (2026-08-11 결정)

같은 코드로 두 시장을 처리하면 **양쪽 다 부정확해진다.** 공시 체계·회계 기준·티커 규칙·거래시간이
전부 다르기 때문이다. `MacroSector`가 "섹터 하나 = 파일 하나"인 것과 같은 이유로,
**시장 하나 = 어댑터 하나**로 나눈다.

| | 🇺🇸 미장 | 🇰🇷 국장 |
|---|---|---|
| 시세·차트 | Yahoo chart API (`lib/macro/parse.parseYahooChart` 재사용) | Yahoo `005930.KS` 가능하나 **지연·결측** → KRX/네이버 계열 검토 |
| 재무·공시 | **SEC EDGAR** (XBRL 태그로 기계 판독. 버블 L1이 이미 씀) | **DART** (Open API, 인증키 필요) |
| 티커 | 알파벳 (`NVDA`) | **6자리 숫자** (`005930`) — 앞 0이 잘리는 사고 주의 |
| 회계 | US-GAAP · 회계연도 제각각 | K-IFRS · 대부분 12월 결산 |
| 컨센서스·목표주가 | 집계처 인용 | 집계처 인용 (§8-① 조건) |
| 수급 | 13F·Form4 (분기·지연) | **투자자별 매매동향**(외국인·기관, 일별) ← 국장이 오히려 유리 |
| 거래시간 | 22:30~05:00 KST(서머타임 변동) | 09:00~15:30 KST |

설계:
```
lib/market/types.ts          MarketAdapter 인터페이스 (quote · financials · disclosure · flow)
lib/market/us.ts             Yahoo + EDGAR
lib/market/kr.ts             DART + 국내 시세·투자자별 매매동향
lib/market/registry.ts       ticker 모양·market 필드로 어댑터 선택
```
⚠ **어댑터가 못 채운 항목은 빈칸 + 조회처**로 내려보낸다(R2). 미국 방식으로 국내 종목을 억지로
채우면 그게 곧 지어낸 숫자다.
⚠ 티커는 **문자열로만** 다룬다. 숫자로 파싱하면 `005930` → `5930`이 된다.

## 6. AI 페르소나 — 글로벌 증권분석가

⚠ **현행 코드와 다르다.** `lib/ai/persona.ts`의 `company-analysis`는 지금
"증권사 리포트를 쓰는 게 아니라 **편입 논리(thesis)**를 쓰는 것이 일입니다"라고 명시한다.
2026-08-11 지시로 페르소나를 **글로벌 증권분석가**로 바꾼다.

바뀌는 것과 바뀌지 않는 것을 나눠 둔다.

**바뀐다 (역할·산출물)**
- 역할: 운용자의 분석 보조자 → **글로벌 증권 분석가**. 국내 종목도 글로벌 피어와 나란히 놓고 본다.
- 산출물: 4문단 thesis → **위 §3의 10섹션 보고서**.
- 문체: 리서치 리포트 문체. 계산 과정을 노출하고, 피어 비교를 기본값으로 둔다.
- 새 페르소나 키 `equity-research` 신설을 권한다 — `company-analysis`(편입 논리 4문단)는
  포트폴리오 화면에서 여전히 쓰이므로 **덮어쓰지 말고 나란히 둔다.**

**바뀌지 않는다 (`WOODSMAN_DOCTRINE`)**
- 매수·매도 권유 금지 · 가격 방향 단정 금지 · 모르는 수치 지어내기 금지 · 성과 보장 금지.
- ⚠ 이 규범은 `/disclaimer`의 법적 고지와 직접 연결돼 있어 페르소나가 덮어쓸 수 없다.

## 7. 저장·화면 설계 (초안)

### 저장 — 코드가 구조, DB가 내용
거시·버블과 같은 원칙. **섹션 구성·규율은 코드**(`lib/report/catalog.ts`), **보고서 내용만 D1.**

```
StockReport      ticker(PK) · name · market · industry · currency
                 version · asOf · status(DRAFT|PUBLISHED) · headline(한 줄 논지)
                 verdictStructural · verdictShort · revokeIf   ← R3
                 nextCheckAt                                   ← R7
StockReportBlock ticker + sectionKey (PK)
                 body(마크다운) · tag · source · sourceUrl · asOf · lookupHint  ← R2·R5
StockReportItem  ticker + itemKey(C..M)  → CANSLIM 축 (points nullable = N/A)  ← R1
StockPeer        ticker + peerTicker · position · strength · weakness
StockTrigger     ticker + kind(EXPAND|HOLD|REDUCE) + order · text
```

### 7-2. Cloudflare에서 보고서는 어디에 저장되나

배포 대상이 Workers(OpenNext)라 저장소 선택이 곧 제약이다. **결론부터: 보고서 본문은 D1,
버전 스냅샷·이미지는 R2.**

**D1 실측 한도** (2026-08-11 확인, `developers.cloudflare.com/d1/platform/limits`)

| 한도 | 값 | 보고서에 미치는 영향 |
|---|---|---|
| 데이터베이스 최대 크기 | 10 GB (유료) / 500 MB (무료) | 보고서 1건 ≈ 60 KB로 잡아도 **무료 등급에서 8,000건** — 넉넉하다 |
| 계정 전체 저장 | 1 TB (유료) / 5 GB (무료) | 여유 |
| 문자열·BLOB·행 최대 | **2,000,000 bytes (2 MB)** | 섹션 본문은 수 KB. ⚠ **이미지를 data URI로 본문에 넣으면 이 벽에 부딪힌다** → R2로 |
| SQL 문 최대 길이 | **100,000 bytes (100 KB)** | ⚠ 값을 SQL에 끼워 넣으면 긴 본문에서 터진다. `?` 바인딩이면 문장은 짧게 유지된다 (CLAUDE.md 4장 규칙이 여기서도 맞다) |
| 쿼리당 바인딩 파라미터 | **100개** | ⚠ 12개 섹션을 한 문장에 몰아 넣지 않는다. 섹션당 1문장 + `batch()` |
| Worker 호출당 쿼리 수 | 1,000 (유료) / 50 (무료) | ⚠ **무료 50**이다. 보고서 저장을 섹션마다 개별 왕복으로 짜면 위험 — `batch()`로 묶는다 |
| 쿼리 최대 시간 | 30초 | 여유 |

**무엇을 어디에 두나**

| 대상 | 저장소 | 이유 |
|---|---|---|
| 보고서 본문(섹션 마크다운·표·태그·출처) | **D1** | 종목 간 비교·정렬·미확정 항목 집계를 하려면 **구조화가 필수**다. 파일로 두면 질의를 못 한다 |
| 렌더 결과 `bodyHtml` | **D1** | ⚠ 글 본문과 같은 단일 경로를 쓴다: 원본 → `lib/markdown` → `lib/sanitize-html` → `bodyHtml`. `bodyHtml`에 직접 쓰지 않는다 |
| 발행본 **버전 스냅샷** | **R2** | 발행 시점의 불변 사본. D1 행은 항상 "현재 버전"만 들고, 과거는 R2에 `reports/{ticker}/{version}.html` |
| 차트 이미지·PDF·원문 클리핑 | **R2** | ⚠ 2 MB 행 한도를 피하는 핵심. 본문에는 **키만** 저장한다 |
| 티스토리용 내보내기 HTML | **생성만, 저장 안 함** | 요청 시 D1에서 만들어 내려준다. 저장하면 원본과 어긋난 사본이 생긴다 |

**⚠ 하지 않을 것**
- **KV에 보고서를 두지 않는다.** KV는 최종적 일관성이라 "저장했는데 화면은 옛것"이 나온다.
  관리자가 고친 즉시 보이지 않으면 목업 시절과 같은 사고다.
- **Workers 정적 자산으로 두지 않는다.** 보고서를 고칠 때마다 재배포가 필요해진다.
- **런타임 Prisma 금지**(CLAUDE.md 4장). `lib/d1.ts` 바인딩으로만 질의한다.

### 화면
- 공개 `/stocks/[ticker]` — 10섹션 렌더. **PUBLISHED만.** 데이터 태그를 색으로 표시.
- 관리자 `/admin/stocks/[ticker]` — 섹션별 편집 + AI 초안 버튼 + 발행 전 **규율 검증**(R2·R3·R5·R6 미충족 시 발행 차단).
- 내보내기 — **티스토리용 HTML**(인라인 style · flex-wrap · 표 가로 스크롤).
  ⚠ 원본 파일 이름이 `_티스토리용`이다. **1순위 목적(티스토리 유입)과 직결**되므로 뒤로 미루지 않는다.

### 단계
```
1단계  lib/canslim(눈금) + lib/report(섹션·규율) 순수 모듈 + 테스트   ← 화면 없이도 검증 가능
2단계  스키마 + repository + 관리자 편집 화면 (수기)
3단계  공개 10섹션 렌더 + 데이터 태그 + 목업 제거
4단계  자동 주입(거시·버블·포트폴리오) 연결
5단계  AI 초안(equity-research 페르소나)
6단계  티스토리용 HTML 내보내기
7단계  시세 실데이터(계획서 C단계) → §02 히어로 KPI·Envelope
```

## 8. ⚠ 열린 결정 — 사람이 정해야 하는 것

### ① 목표주가를 낼 것인가 (가장 중요)
정면 충돌이다.

- `WOODSMAN_DOCTRINE`: "**목표주가를 제시하지 않는다.**" `/disclaimer`와 연결된 문장.
- 한국콜마 §07: "목표주가는 제시하지 않는다" — **규범과 일치**.
- 두산 보고서: 목표주가 **34,200원**, 투자판단 **매수/중립/관망** — **규범과 충돌**.

**→ 결정 (2026-08-11, 사용자): 우리가 산출하지 않고 「증권사에 나온 데이터를 인용해 보여준다」.**

이건 규범과 충돌하지 않는다. `WOODSMAN_DOCTRINE`이 금지하는 것은 **우리가 목표주가를 제시하는 것**이고,
제3자가 이미 공표한 수치를 **출처와 함께 옮기는 것**은 사실 보도다. 두산 보고서도 자기 산출값과
"증권사 컨센서스 평균 118,833원(Investing.com 집계, 2026.03.23)"을 **다른 줄에** 두었다.

지킬 조건 (R4로 코드가 강제한다):

| 조건 | 이유 |
|---|---|
| **출처·집계처·기준일 필수** (예: "18개사 컨센서스 · Investing.com 집계 · 2026-03-23") | 날짜 없는 목표주가는 우리 의견처럼 읽힌다 |
| **제3자 수치임을 화면에 표기** — 컨센서스 배지 | 사이트 판단과 시각적으로 분리 |
| **우리 모델은 목표주가를 만들지 않는다** | AI 출력·CANSLIM·밸류에이션 섹션에서 목표주가 생성 금지는 그대로 유지 |
| **밸류에이션 산출값은 "목표주가"라 부르지 않는다** | "PBR 3.0배 적용 시 산출값"으로 표기하고 방법론 한계(R6) 병기 |
| **컨센서스와 우리 산출값이 벌어지면 그 이유를 쓴다** | 두산 사례: "증권사는 EV/EBITDA를 쓰므로 괴리". 괴리 자체가 정보다 |

⚠ 남은 확인: 컨센서스 수치의 **재배포 조건**(집계처 이용약관). 수동 입력·출처 표기 범위에서 시작하고,
자동 수집을 붙이려면 그때 다시 본다.

### ② 보고서 생성 주체
AI 초안 → 사람 확정(권장) / 사람이 전부 작성 / 외부 HTML 반입. §7 5단계의 범위가 달라진다.

### ③ 비공개 보고서를 둘 것인가
두산 보고서처럼 결론이 강한 문서는 사이트 공개 대신 **관리자 전용**으로 둘 수 있다.
