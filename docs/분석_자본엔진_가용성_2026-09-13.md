## 0. 결론 다섯 줄

1. ⭐ **연준의 장기금리 책무는 「숨은」 것이 아니다. 법에 명시돼 있다.** 원문으로 확인했다.
2. ⭐ **가설의 시험대가 지금이다.** 생산성 +2.24%(전년비) · 단위노동비용 +1.40%로 **공급 쪽은
   실제로 좋아지고 있는데**, 시장은 9/16 인상을 92%로 걸고 있다(수요 축소 쪽).
3. ⚠ **PRYS(생산성 − 실질금리)가 0 근처다** — −0.02 ~ −0.31%p. 실질 자금비용이 생산성 수익률을
   **막 따라잡았다.** 가설이 갈리는 바로 그 지점에 숫자가 서 있다.
4. ⭐ **미 재무부 Fiscal Data API가 열려 있다(무료·키 없음).** 네 번째 자동 출처다.
   재정→민간 전달(§10)과 자본 경쟁(§12)의 원재료가 확보됐다.
5. ⚠ **권장 스택(FastAPI·Postgres·Redis·Celery)은 쓰지 말아야 한다.** 요구서 §34가 「불필요한
   별도 애플리케이션을 만들지 않는다」고 했고, 이 사이트는 Cloudflare Workers + D1이다.

## 1. ⭐ 연준의 세 번째 책무 — 「숨은」 것이 아니라 법에 쓰여 있다

연방준비법 **제2A조**(Monetary Policy Objectives) 원문. 출처는 연준 자신의 페이지다.
<https://www.federalreserve.gov/aboutthefed/section2a.htm>

> "The Board of Governors of the Federal Reserve System and the Federal Open Market Committee
> shall maintain long run growth of the monetary and credit aggregates commensurate with the
> economy's **long run potential to increase production**, so as to promote effectively the goals
> of **maximum employment, stable prices, and moderate long-term interest rates**."

### ⚠ 두 가지를 바로잡는다

| 흔한 말 | 사실 |
|---|---|
| 「연준의 책무는 물가·고용 둘(dual mandate)」 | ⚠ **법은 셋을 적었다.** 「dual」은 관행적 축약어다 |
| 「장기금리 관리는 **숨은** 책무」 | ⚠ **숨어 있지 않다. 명시돼 있다.** 숨은 것은 「어떻게」이지 「무엇을」이 아니다 |

⭐ **그리고 더 큰 것이 이 문장 안에 있다.** 법은 통화·신용 총량을 「경제의 **장기 생산 잠재력**에
상응하게(commensurate with the economy's long run potential to increase production)」 유지하라고
적었다. **가설의 법적 근거가 여기다** — 「수요를 죽여 물가를 잡는다」가 아니라 「잠재생산에 맞춰
통화·신용을 키운다」가 법의 문장이다.

### ⚠ 그러나 여기까지가 Fact다

| 주장 | 등급 | 왜 |
|---|---|---|
| 연준 책무에 「moderate long-term interest rates」가 있다 | **Fact** | 제2A조 원문 |
| 법이 통화·신용을 **잠재생산**에 맞추라고 적었다 | **Fact** | 같은 문장 |
| 연준이 10년물을 **특정 수준으로 겨냥**한다 | **Rejected** | 그런 발표도 규정도 없다 |
| 연준이 QT 속도·레포로 장기금리를 **사실상 관리**한다 | **Inference** | 관측과 정합하나 연준이 그 목적을 말한 적 없다 |
| 재무부 부채 조달을 돕는 **재정 지배(fiscal dominance)**다 | **Hypothesis** | 시장의 해석이다. 우리 화면이 단정하지 않는다 |
| 미 정부가 공급주의로 **선회했다** | **Inference** | 정책 결과로는 보이나 공식 의도 표명이 아니다 |

⚠ 요구서 §31이 금지한 문장(「Fed가 장기금리를 직접 통제한다」)과 §30의 「Evidence: Rejected」가
정확히 이 자리다. **셋을 섞어 쓰면 제일 강한 주장(Fact)이 제일 약한 주장(Hypothesis)의 신뢰도까지
끌어내린다.**

## 2. ⭐ 지금 나오는 숫자 — 가설의 시험대가 열려 있다

모두 2026-09-13에 직접 받아 계산했다.

### 공급 쪽은 실제로 좋아지고 있다

| 지표 | 계열 | 값 |
|---|---|---|
| 노동생산성 전년비 (2026Q2) | `OPHNFB` | **+2.24%** |
| 같은 것, 4분기 평균 | `OPHNFB` | **+2.53%** |
| 최근 6분기 추이 | | +1.97 → +2.08 → +2.46 → +2.49 → **+2.93** → +2.24 |
| 단위노동비용 전년비 | `ULCNFB` | **+1.40%** |

⚠ **계열 단위를 확인해야 했다.** `PRS85006092`는 「전년비」가 아니라 **연율 분기변화**다(FRED
시리즈 페이지로 확인). 그걸 전년비로 읽으면 생산성이 1.4%로 보이고 **PRYS가 1%p 가까이 틀린다.**
그래서 수준 계열(`OPHNFB`)에서 전년비를 직접 계산했다. 「단위·부호를 먼저 확인한다」가
이번에도 값을 살렸다.

### 그런데 시장은 수요 축소를 걸고 있다

| 지표 | 값 |
|---|---|
| 선물 내재 10월 평균 실효금리 (`ZQ=F`) | **3.860%** |
| 현재 실효금리 (`FEDFUNDS`) | 3.63% |
| 내재 변화 | **+0.230%p** → 9/16 회의 25bp 인상 한 번 기준 **92%** |

### ⚠ 그리고 자금비용이 생산성을 막 따라잡았다

```text
PRYS = 추세 생산성 증가율 − 실질 10년 금리
```

| 계산 | 값 |
|---|---|
| 최근분기 2.24% − 실질10Y 2.55%(`DFII10` 9/10) | **−0.31%p** |
| 4분기 평균 2.53% − 2.55% | **−0.02%p** |

⭐ **거의 정확히 0이다.** 생산성이 벌어 주는 실질 수익률과 돈을 빌리는 실질 비용이 같은 지점에
서 있다. 조금만 더 실질금리가 오르면 CAPEX는 수익률로 비용을 못 덮는다.

### 반대로 부채 지속가능성 쪽은 아직 여유가 있다

| 지표 | 값 |
|---|---|
| 명목 GDP 전년비 (2026Q2) | **+6.56%** |
| 10년 국채 (`DGS10` 9/10) | 4.95% |
| **Growth-Funding Spread** | **+1.61%p** |

⚠ **두 계기판이 엇갈린다.** 명목성장이 자금비용보다 높아(+1.61%p) **정부 부채는 굴러가는데**,

**포털의 첫 화면이 이 두 숫자여야 한다.**

## 4. ⚠ 지금 정해야 하는 것 — 스택

요구서 §33은 `FastAPI · Python · PostgreSQL · Redis · Celery · Docker`를 권했다.
그런데 §34 마지막 줄은 이렇게 적혀 있다 — 「**불필요한 별도 애플리케이션을 만들지 않는다.**」

⚠ **이 둘은 같이 갈 수 없다.** 이 사이트는 Cloudflare Workers(OpenNext) + D1이고,
Postgres·Redis·Celery는 **상시 켜진 서버**를 요구한다. 그러면 배포·비용·장애 지점이 두 벌이 되고,
무엇보다 **지표 판단이 두 곳에 생긴다** — 이 저장소가 가장 크게 데인 사고가 그것이다.

⭐ **권고: 지금 스택을 그대로 쓴다.** 필요한 것이 이미 다 있다.

| 요구서가 원한 것 | 여기서 대응하는 것 |
|---|---|
| Python 스코어링 | `lib/macro/*` 순수 함수 + vitest (이미 1,122개) |
| PostgreSQL | D1 (`MacroPoint` 등 50개 테이블) |
| Celery / APScheduler | Cloudflare Cron (`0 21 * * *`, 스스로 깨어나는 것 확인됨) |
| Redis | ⚠ **필요 없다.** 원값을 저장하고 읽을 때 계산하는 구조다 |
| Plotly / ECharts | 지금 쓰는 SVG 차트 (`overlay.ts`) |
| FastAPI | Next 서버 컴포넌트 + 서버 액션 |

## 5. 추가 요청 두 가지 — 어디에 넣을지

### (1) 「지표 설명에 내 인사이트가 녹아 있게」

⭐ 자리가 이미 있다. 지표마다 `what`(이게 뭔가) · `why`(왜 보나) · `read`(어떻게 읽나)를
쓰고 있다. 여기에 **엔진 축과 가설을 더한다.**

```ts
engine: "productivity"        // 7개 힘 중 어디에 속하나
hypothesis: ["H2", "H4"]      // 이 지표가 가르는 가설
claim: "Fact" | "Inference" | "Hypothesis"
narrative: "..."              // ⭐ 조망 — 이 숫자가 큰 그림에서 무슨 뜻인가
```

⚠ `read`는 **읽는 법까지만** 쓴다는 규칙이 이미 있다(매매 판단으로 안 넘어간다). `narrative`는
그 선을 지키면서 **구조를 말하는** 자리다 — 「이 숫자가 오르면 사라」가 아니라 「이 숫자가
오르면 수요 축소 쪽 힘이 세진다」.

⚠ **차트에도 기준선을 긋는다.** `series.ts`에 기준선 개념이 이미 있다. PRYS는 **0**이 기준선이고
(생산성 = 실질 자금비용), Growth-Funding Spread도 **0**이다. 선이 없으면 독자가 −0.31%p가
좋은지 나쁜지 모른다.

### (2) 「용어와 근거에 URL을 달아 독자가 확인할 수 있게」

⚠ **지금 없는 계층이다. 새로 만들어야 한다.** 지표마다 원 출처 `url`은 있지만 **용어**를
설명하는 자리와 **주장의 근거**를 대는 자리가 없다.

| 만들 것 | 무엇 | 왜 |
|---|---|---|
| `lib/macro/glossary.ts` | 용어 → 뜻 한 줄 + **1차 출처 URL** | 기간프리미엄·단위노동비용·잠재산출·신용충격을 본문에서 누르면 바로 확인 |
| 근거 링크 | 주장마다 등급 + URL | 예: 연준 셋째 책무 → **Fact** → 제2A조 원문 링크 |
| 지표 카드의 「숫자 확인」 | FRED 시리즈 페이지 직링크 | 이미 `url`이 있다. **화면에 더 크게 낸다** |

⭐ **이게 곧 AI 검색 대응이기도 하다.** 1차 출처를 문장마다 달아 두면 AI가 인용할 때 우리 링크를
함께 가져간다. 그리고 ⚠ `docs/계획_AI친화_사이트_GEO.md`의 「한 문장 요약」이 **아직 화면에 안
붙어 있다**(`fedHikeSentence`·`fedFuturesSentence` 둘 다 함수만 있다). 이번에 같이 붙이는 것이 맞다.

## 6. 짓는 순서 — 35개 절을 한 번에 짓지 않는다

⚠ 「변경은 하나씩 배포」다. 그리고 **점수(score)부터 만들지 않는다** — 원자료가 없는 종합점수는
그럴듯한 숫자를 만들어 낸다. 아래 순서는 **원자료 → 관계 → 점수 → 종합**이다.

| 조각 | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **A** | ⭐ **PRYS · Growth-Funding Spread 두 지표**(파생) + 기준선 0 | 원자료가 **오늘 다 있다**. 첫 화면의 결론이고, 가설이 갈리는 지점이다 |
| **B** | 생산성·공급 계열 6개 + 새 묶음 「생산성·공급」 | A의 근거. PDI(§7)의 원자료 |
| **C** | 신용창출 계열 6개 + 재무부 API 어댑터 | H3/H5의 원자료. ⚠ 네 번째 자동 출처를 붙이는 일이라 별도 배포 |
| **D** | 용어 사전 + 근거 등급 계층 (§5-(2)) | 여기까지 오면 설명할 것이 쌓인다 |
| **E** | 점수화 (PDI · Capital Formation · Credit Creation …) | ⚠ **원자료가 다 있는 축만** 점수를 만든다. 빈 축은 「못 받는다」로 남긴다 |
| **F** | Regime 판정 (R1~R8) · 다이어그램 · AI 해석 계층 | 점수가 실제로 움직이는 걸 본 뒤에 |

⚠ **A를 먼저 하는 이유가 하나 더 있다.** 지금 `zq_front`에 값이 0점이다. A를 붙이면 같은 화면에
「시장이 거는 것(92%)」과 「생산성이 버는 것(PRYS 0 근처)」이 나란히 서고, **그 대비가 첫 글감**이다.
