# 홈을 콘텐츠로 열고, 계좌를 증거로 붙인다

> 한 줄: **입구를 "내 계좌"에서 "지금 시장에 부는 바람"으로 바꾸고,
> 계좌·종목분석은 그 흐름에 대한 나의 답으로 뒤에 붙인다.**

---

## 1. 왜 바꾸나

### 지금의 홈 순서

| # | 블록 | 무엇 |
|---|---|---|
| 1 | 히어로 | 문구 + **계좌 평가액·수익률·목표 구성비**, 첫 버튼 「계좌 성과 보기」 |
| 2 | 자금 흐름 | 납입원금 vs 평가액 차트 |
| 3 | 거시 지표 | 침체 신호 5 + 헤드라인 지표 4 |
| 4 | 운영 원칙 | 3장 |
| 5 | 홈 섹션 글 | `SectionFrame` |
| 6 | 최신 인사이트 | 3편 + **티스토리 CTA** |
| 7 | 투자일지 + 종목 보고서 | |

### 세 가지가 이 순서를 배신하고 있다

1. ⚠ **1순위 목적과 어긋난다.** 성과 지표는 「티스토리로 넘어간 클릭」인데(운영지침 §4),
   히어로의 첫 버튼은 내부 링크(`/portfolio`)이고 **티스토리 CTA는 6번째 섹션**에 있다.
   검색으로 들어온 사람이 거기까지 내려갈 이유가 없다.
2. **검색 유입은 계좌에서 나오지 않는다.** 남의 계좌 평가액을 검색하는 사람은 없다.
   「장단기 금리차 역전」·「미시간 소비심리」를 검색하는 사람은 있다. 지금 이 사이트에서
   검색·AI 인용에 가장 강한 자산은 **지표마다 what·why·read가 붙은 거시 카탈로그**인데
   홈에서 3번째 자리에 있다.
3. **계좌가 비어 있어 홈이 실제로 비어 있다.** `perf`가 `null`이면(스냅숏 0건)
   히어로 카드와 자금흐름 섹션이 **통째로 안 그려진다.** 계좌 중심으로 설계된 홈에서
   계좌가 비면 뼈대만 남는다 — 지금 운영본이 그 상태다.

## 2. ⚠ 운영지침과 부딪히는 지점 (먼저 말하고 결정받은 것)

`docs/운영지침.md` §4는 이렇게 적혀 있다.

> 사이트 고유 콘텐츠(계좌 공개·투자일지)가 검색 유입을 만드는 미끼다. **약화시키지 않는다.**

홈에서 계좌를 내리는 것은 이 문장과 정면으로 부딪힌다. 그래서 지침 §0대로 **먼저 말하고**
사용자가 정했다. 결정은 다음과 같다.

| 쟁점 | 결정 | 근거 |
|---|---|---|
| 계좌를 홈에서 어떻게 하나 | **지우지 않고 「얇은 띠」로 강등** | 지우면 고유 콘텐츠가 사라져 §4를 실제로 위반한다. 남의 지표 요약은 흔하지만 **지표를 읽고 실제로 그렇게 굴린 기록**은 흔하지 않다 — 그것이 유일한 차별점이다 |
| 블록 순서·노출의 관리 | **이번엔 코드 고정**, 데이터화는 나중 | 형태가 자리잡기 전에 설정 화면부터 만들면 아무도 안 쓰는 스위치가 남는다(운영지침 §1의 "죽은 버튼" 금지와 같은 이유) |

⚠ **이 설계를 구현하면 `docs/운영지침.md` §4와 `docs/woodsman_개발요구서_v2.md`의 홈 기술,
`app/(public)/page.tsx` 상단 주석("첫 화면에서 바로 넣은 돈이 얼마가 됐는지 보여준다")을
같이 고친다.** 문서가 뒤처지면 다음 점검이 거짓말을 한다.

### 무엇이 어디로 가나

- **자금 흐름 차트 → `/portfolio`로 이관.** 이미 `/portfolio`에 같은 차트가 있다
  (`portfolio/page.tsx:120`). 홈에서 빼면 **중복이 사라지는 것이지 기능이 주는 게 아니다.**
- **계좌 상세 카드(평가액·원금·리밸런싱 메모) → `/portfolio`.** 홈에는 H5 한 줄만 남는다.
- ⚠ `DataModeNotice`는 **H5와 함께 홈에 남는다.** 계좌 숫자가 한 줄이라도 나오면
  모의/실계좌 표시는 의무다(운영지침 §5 · CLAUDE.md §6).

## 4. 모듈 구조

`web/CLAUDE.md` §1 그대로 — **판단은 `lib`, 화면은 `features/*/ui`, 라우트는 조립만.**
지금 `app/(public)/page.tsx`는 **400줄**이고 그 안에 조립·판단·문구가 섞여 있다.

```
src/lib/home-layout.ts        ← 순수 판단 + 테스트
    homeBlocks(input): Block[]   어떤 블록을 어떤 순서로 그릴지
    ⚠ "값이 없으면 뺀다"와 "값이 없다고 적는다"를 여기서 한 곳으로 정한다

src/lib/home-lede.ts          ← 순수 함수 + 테스트
    macroLede(overview): string | null
    거시 요약을 히어로 한 문장으로. ⚠ 값이 없으면 null — 지어내지 않는다

src/features/home/ui/HeroContent.tsx     H1
src/features/home/ui/MarketWindBoard.tsx H2 (RecessionBoard를 감싼다)
src/features/home/ui/LatestPosts.tsx     H3
src/features/home/ui/AccountStrip.tsx    H5  ← 새로 만드는 유일한 화면 조각
src/features/home/ui/PrinciplesGrid.tsx  H9

src/app/(public)/page.tsx     ← 데이터 로드 + 블록 조립만. 판단·문구 없음
```

⚠ `AccountStrip`은 `features/portfolio`가 아니라 `features/home`에 둔다 —
**홈 전용 요약 표현**이고, `/portfolio`의 상세 카드와 같은 것이 아니다.
같은 판단(수익률·구성비)은 기존 `lib/performance.ts`·`lib/bucket-target.ts`를 그대로 부른다.
**같은 판단을 두 번 구현하지 않는다**(운영지침 §1).

## 5. 단계 — 하나씩, 되돌릴 수 있게

각 단계는 **그 자체로 배포 가능**해야 한다. 한 번에 다 갈아엎으면 어디서 깨졌는지 모른다.

### Step 0 — 선행 조건 (코드 아님)

⚠ **콘텐츠 중심 홈은 글이 6~8편은 있어야 형태가 산다. 지금 2편이다.**
H3가 2칸만 차 있으면 재편의 효과가 안 보인다. 오늘 계획의 A 목록(거시 자료 가져오기 ·
첫 보고서 발행)이 **이 재편의 선행 조건**이다.

- 완료 기준: 발행 글 6편 이상 **또는** 사용자가 "2편으로도 간다"고 정함

### ✅ Step 1 — 모듈화 (⚠ 겉모습 변화 0) — **완료 2026-08-30**

지금 홈을 **한 줄도 다르게 보이지 않게** 블록으로 쪼갠다. 재배치는 다음 단계에서 한다.
섞으면 "쪼개다 깨진 것"과 "옮기다 깨진 것"을 구분할 수 없다.

- 만드는 것: `lib/home-layout.ts`(+테스트) · `features/home/ui/*` 5개
- 고치는 것: `app/(public)/page.tsx` → 조립만 (400줄 → 100줄 내외)
- 완료 기준: `npm run check` 통과 · **로컬 홈을 띄워 눈으로 대조** · 블록 판단 테스트 통과
- 되돌리기: 이 커밋만 revert

⭐ **완료 확인(2026-08-30)**: 같은 데이터로 옛 코드와 새 코드의 렌더 결과를 해시로 비교했다 —
`5893fe53f78a140f` (36,656자)로 **바이트 단위 동일**. 라우트 400줄 → 133줄, 테스트 6개 추가.

### ✅ Step 2 — 계좌를 띠로 강등 · 자금흐름을 `/portfolio`로 — **완료 2026-08-30**

- 만드는 것: `features/home/ui/AccountStrip.tsx`
- 옮기는 것: 히어로 계좌 카드 · 자금흐름 섹션 → `/portfolio`(중복 제거 확인)
- ⚠ 지키는 것: `DataModeNotice`가 H5와 함께 남는가 · 「목표 구성비」 라벨이 붙어 있는가
  (2026-08-17 점검에서 지적된 자리 — 라벨 없이 그리면 현재 비중으로 읽힌다)
- 완료 기준: 스냅숏 0건 상태에서도 H5가 **"아직 스냅숏이 없습니다"로 보인다**
  (⚠ 빈 칸을 0원으로 만들지 않는다)

⭐ **완료 확인(2026-08-30)**: 히어로에 계좌 카드 없음 · 홈에 자금흐름 차트 없음 ·
계좌 띠와 모의 표시 있음 · `/portfolio`에 자금흐름·평가액·최근 리밸런싱 그대로 있음.
⚠ 첫 화면 **문구(`heroSubtitle`)는 아직 계좌 이야기**다 — 관리자가 고치는 운영값이라
코드가 바꾸지 않았다. 사람이 정할 일로 남겼다.

### Step 3 — 콘텐츠 히어로

- 만드는 것: `lib/home-lede.ts`(+테스트)
- 고치는 것: H1 CTA 2개(`/macro` · `/go/tistory`) · H2를 히어로 바로 아래로 · H3를 6편으로
- ⚠ **티스토리 링크는 반드시 `/go/…` 경유.** 직접 걸면 나가는 클릭이 안 세지고
  1순위 지표가 빈다(2026-08-25 결정)
- 완료 기준: 거시 값이 없을 때 히어로가 **한 문장을 지어내지 않는다**(`macroLede`가 null)

### Step 4 — `/portfolio` 보강

홈에서 내려온 것이 `/portfolio`에서 **첫 화면**이 되게 순서를 정리한다.
포트폴리오는 이제 "흐름에 대한 나의 답"이라는 자리를 갖는다 — 페이지 머리말도 그렇게 고친다.

- 완료 기준: 홈과 `/portfolio`에 **같은 차트가 두 번 나오지 않는다**

### Step 5 — SEO · GEO

홈의 성격이 바뀌면 **검색과 AI가 읽는 문장도 같이 바뀌어야 한다.** 화면만 고치고 메타를
두면 "화면은 콘텐츠, 검색결과는 계좌"가 된다 — 2026-08-25에 같은 부류의 사고가 있었다.

- 고치는 것: 홈 `metadata`·`openGraph` · JSON-LD · `features/ai/knowledge.ts`
- ⚠ 안 보이는 자리에는 `stripEmphasis`를 쓴다(별표가 검색결과로 새지 않게)
- 완료 기준: 운영본 홈 소스에서 **별표 0개** · description이 콘텐츠 사이트로 읽힌다

### Step 6 — 점검 · 배포 · 검증

- `npm run dev` **끄고**(⚠ Windows에서 `pkill -f`는 node를 못 잡는다 — `Get-CimInstance`로 센다)
  `.next` 지우고 `npm run check`
- 배포 → **운영본 검증**(로컬 통과가 배포 성공이 아니다)
- `web/CHANGELOG.md`에 **왜**, `docs/woodsman_개발요구서_v2.md`에 **지금의 상태**,
  `docs/운영지침.md` §4에 **바뀐 원칙**

## 6. 이 설계가 지키는 것

- **빈 칸을 0으로 만들지 않는다** — H2·H5는 값이 없으면 "없다"고 적는다.
- **같은 판단을 두 번 구현하지 않는다** — 수익률·구성비는 기존 순수 모듈을 부른다.
- **죽은 버튼을 두지 않는다** — 블록 설정 화면은 이번에 만들지 않는다(§2 결정).
- **모의/실계좌 표시는 계좌 숫자를 따라간다** — 띠로 줄어도 표시는 따라 내려간다.
- **나가는 클릭은 `/go/…`로만** — 1순위 지표가 비지 않게.

## 7. 열어 둔 것

- **블록 순서·노출의 데이터화**(`HomeBlock` 테이블 + `/admin/home` 토글) — 형태가 자리잡은 뒤.
  운영지침 §1의 설계사상에는 이쪽이 맞다. 공수 +1.0~1.5 세션.
- **거시 한 줄 요약의 문장 품질** — 지금은 규칙 기반. AI로 다듬는 것은 별건으로 본다
  (⚠ 유료 제공자 월 토큰 상한 규칙이 걸린다).
