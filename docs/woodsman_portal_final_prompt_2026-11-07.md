목표는 공개 페이지의 완성도, 금융 데이터의 신뢰성, 콘텐츠의 유용성을 높이는 것입니다.
AdSense 승인을 보장한다고 표현하지 말고, 사용자와 검색엔진에 동일한 콘텐츠를 제공하세요(심사 봇 전용 분기 금지).
가짜 기록·가짜 수익률·가짜 스냅숏은 어떤 형태로도 만들지 마세요.

먼저 저장소의 지침(CLAUDE.md, docs/), 기술 스택, 데이터 흐름, 관련 컴포넌트를 확인하세요.
아래 관찰은 2026-11-07 KST 공개 페이지 기준이므로, 현재 코드와 배포 사이트에서 재확인한 뒤 수정하세요.
재확인 결과가 다르면 수정하지 말고 보고하세요.

## 작업 전 확인
- 포털 소스 저장소 위치를 먼저 확인하세요(참고: D:\P1.VideCoding\3. StockMng, 개발요구서 docs/woodsman_개발요구서_v1.md). 다른 저장소라면 그 위치를 보고하세요.
- 작업은 P0 → P1 → P2 순서로, 우선순위 단위로 커밋하고 각 단계마다 변경 요약을 보고하세요.
- 콘텐츠 문구(소개·푸터·고지문)를 바꿀 때는 바꾸기 전·후 문장을 표로 보고하고, 운영자 확인 전에는 배포하지 마세요.

## P0-1. '공사 중'으로 읽히는 요소 정리
- /macro, /macro/rates, /insights의 "BETA · 개발 중인 베타 사이트입니다" 배너:
  사이트 단위 배너를 제거하고, 실험적 산출물만 해당 카드에 '실험 지표 · 산식 검증 중'으로 표시.
- 공개 화면에서 내부 문구 제거·교체:
  - "아직 저장된 분석이 없습니다 — 운영자가 분석을 올리면 여기에 보입니다." → 해당 하위 영역을 숨기거나 계산 근거·해석 방법 안내로 대체
  - "docs/금리섹션_지표해설.md가 단일 출처입니다" → 독자용 '지표 해설' 링크로
  - "부분 산출 — policy_stance 레이어가 빠졌습니다" → "정책 기조 요소 미반영 · 부분 산출치"
  - 상단 지표 띠의 "모름": 코드에서 의미를 확인한 뒤(방향 미산출인지 등) 아래 상태 모델로 매핑

## P0-2. 실계좌/모의 투자 표현 통일
- 고지문은 "대표 포트폴리오와 투자일지는 모의 투자 기록입니다. 매매와 납입은 가상입니다."
- 푸터 "운용 중인 계좌의 성과를 그대로 공개합니다", 소개 "자신의 투자 계좌를 공개"를 모의 투자 기준으로 수정.
- 시세는 실제 시장가격, 매매·납입은 가상이라는 구분을 /portfolio, /journal 상단에 한 줄로 명시.

## P1-1. 데이터 갱신과 정합성
- 홈 10년물 4.90%(2026-11-04)인데 /macro·/macro/rates는 5.18%(2026-09-24), 침체 신호 기준일도 홈 11-07 vs /macro 09-26.
  /macro 하위 페이지가 정적 생성 후 갱신되지 않는지, 캐시·빌드·크론을 점검하고 원인을 보고하세요.
- 같은 페이지 불일치: /macro 타일 순유동성 5.80조·TGA 0.95조 vs 카드 5.77조·0.98조. 지표 개수 홈 116 vs /macro 115.
  ISM PMI 배지가 홈 '기한초과', /macro '정상'. 지표별 단일 출처·단일 상태 계산 함수로 통일.
- 리밸런싱 횟수: /portfolio "총 1회(2026-10-26)" vs /journal "리밸런싱 0회". 집계 원천을 하나로.

## P1-2. 공통 상태 모델
- 상태: 정상 / 발표 주기상 정상 지연 / 이전 유효값 사용 / 갱신 지연 / 값 미제공 / 비교 이력 부족 / 산출 기준 미충족 / 조회 실패 / 비적용.
- 표시 예: "최근 확인값 · YYYY.MM.DD 기준", "갱신 지연 · YYYY.MM.DD 기준", "추세 비교 자료 부족", "자료 미제공", "데이터를 불러오지 못했습니다".
- 갱신 일정이 실제로 없으면 '업데이트 예정'이라고 쓰지 말 것. 기준일을 실제보다 최근으로 표기하지 말 것.
- 데이터 기준일·수집일·계산일을 구분. 월간·분기 지표의 정상 발표 지연(예: 월간 지표의 다음 달 발표)을 오류로 처리하지 말 것.
- null/undefined/NaN/Infinity/잘못된 날짜/빈 배열 방어. 결측을 0·보합·정상으로 변환 금지. 배지 줄바꿈·모바일 점검.

## P1-3. 요약 문장과 판정 일치
- 홈 침체 요약 "5개 지표가 모두 기준선 안쪽입니다"가 기한을 넘긴 ISM 값(2026-08-01)을 그대로 세고 있음.
  요약 문장을 판정 데이터에서 생성하고, 지연·결측 입력이 있으면 "1개 지표는 지연된 값 기준"처럼 영향 표시.
- VIX가 5개 침체 지표에 포함되는지 확인하고, 별개 체계면 카드 근처에 차이 설명.
- GCRM '엔진 온도 72(평소보다 크게 높다)'와 포털 '경기 엔진 온도 53(평소 수준)'은 다른 모델로 보임.
  유동성에는 이미 있는 "다른 모델입니다" 설명을 엔진 온도에도 추가. 두 점수를 합치지 말 것.

## P2-1. /portfolio
- 현재 상태: 100종목, 구성 65.6%, 성장 84.4% / 인컴 13.1% / 방어 2.5% (목표 50/30/20).
- 50/30/20은 '목표'로 표시하고, 현재 배분을 목표에 맞춘 숫자로 바꾸지 말 것. 기존 종목을 임의 ETF로 교체 금지.
- 스냅숏 0개: 빈 차트 대신 목표 배분·현재 확인 가능한 배분·목표 대비 편차·자산별 역할·리밸런싱 원칙.
  스냅숏 1개: '현재 구성 카드'. 추이는 2개 이상 이력이 있을 때만. 과거 곡선 생성 금지.
- 수익률을 표시하면 계산 방식·기간·납입/인출·배당/수수료 처리 기준을 명시.
  가격 기준일(현재가 2026-10-26 수동 입력)과 환율 기준일(2026-11-06)이 다르면 각각 표시.
- '구성 완료 65.6%'의 산식 확인. 이해하기 어려우면 목표 대비 편차로 대체.
- 종목 카드 반복 "목표비중—"은 생략하거나 "개별 목표 미설정"을 한 번만 설명.
  "판정 2026-10-23 · 오래됨"은 상태 모델의 '이전 유효값 사용 · 기준일'로.

## P2-2. 투자일지
- 공개 가능한 실제 판단 기록이 저장소/DB에 있는지 먼저 확인하고, 있으면 최신 3~4개 표시.
- 없으면 가상 일지를 만들지 말 것. 빈 상태는 운영 원칙('매매 전에 판단을 기록한다')과 기록 형식 설명 +
  관련 인사이트 링크(‘관련 분석’으로 구분)로 대체.
- 교육용 사례를 추가할 경우 투자일지와 분리된 경로(/cases 등)에 두고, 카드·본문에 '교육용 가상 사례'를 명시.
  작성일과 분석 대상 시점을 구분하고, 시장 수치는 출처·기준일 검증된 것만 사용.
  (주의: 2025-12-01 연준 QT 종료 등 최신 사실과 충돌하는 전제를 쓰지 말 것)

## P2-3. 콘텐츠와 검색
- sitemap.xml에 공개된 인사이트 전부(현재 7편 중 2편만 등재)와 /blog 반영. 관리·로그인·가입 페이지 제외 유지.
- 본문 있는 상세 페이지에 title·description·canonical. 티스토리와 같은 글은 원문 canonical 정책을 정해 적용.
- 없는 상세 페이지는 404 유지(현재 4xx 확인됨) — 정확한 상태 코드 확인.
- 오류·관리·빈 결과 화면의 광고 노출 점검.
- 이미 정상인 항목(달력 D-day KST 계산, 지난 일정 분리)은 회귀 테스트만.
- 기존 디자인과 '파도·바람·조류' 표현 유지.
