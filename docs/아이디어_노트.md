## 2026-08-11 — `_published` 발행본 3건에서 건진 것

출처: `D:\Woodsman\Investor\_published\` (한국콜마 · LG이노텍 · 두산에너빌리티)
→ 대부분 **설계서 §2·§3**으로 승격했다. 여기에는 **승격하지 못한 것과 확장 아이디어**만 남긴다.

### A1. 보고서에 "검증 주기"를 필드로 둔다 ⭐
한국콜마 §운용노트: *"매월 1일 전후 산업부 수출입동향의 화장품 항목 하나가 사실상의 월간 성적표다."*

논지를 세울 때 **그 논지를 얼마나 자주 검증할 수 있는지**가 논지의 질을 좌우한다.
분기 실적으로만 확인되는 논지와 월간 통계로 확인되는 논지는 다루는 법이 달라야 한다.

→ `StockReport.verifyCycle`(월간/분기/반기) + `verifySource`(무엇을 보면 되나) + `verifyNextAt`.
→ 이게 있으면 **관리자 홈에 "이번 주 검증할 종목"이 자동으로 뜬다.** 보고서가 살아 있게 되는 장치다.

### A2. 논지 철회 조건을 알림으로 건다 ⭐⭐
한국콜마 §06: *"ΔYoY가 2개월 연속 마이너스로 꺾이는 순간이 이 판정의 공식 철회 조건이다."*

철회 조건을 **글로만 적으면 아무도 안 본다.** 사이트는 이미 거시 지표를 D1에 쌓고 있으므로,
철회 조건을 지표 키 + 비교식으로 적으면 **기계가 감시**할 수 있다.

→ 버블 모니터의 하드 트리거와 **같은 구조**다. `StockTrigger`를 버블 `BubbleTriggerState`처럼
`fired` 상태를 갖는 형태로 설계하면 두 화면이 같은 부품을 쓴다.
→ 발화 시 `/admin` 최상단에 뜬다. "논지가 깨졌다"는 것이 가장 중요한 알림이다.

### A3. 한 화면에서 종목 간 축 비교
두산 보고서의 힘은 **피어 3사를 같은 표에 놓은 것**이다. 단독 평가는 기준이 없다.

→ 보고서가 D1에 구조화되면(설계서 §7) `/stocks`에서 **보유 종목 전체의 CANSLIM 축 비교표**를
자동 생성할 수 있다. 개별 보고서를 쓴 부산물로 포트폴리오 전체 지도가 공짜로 나온다.
→ ⚠ 단, 기준일이 다른 점수를 나란히 놓으면 오해가 생긴다. **열마다 기준일을 함께** 찍는다.

### A4. Envelope 밴드는 계산으로 낼 수 있다
LG이노텍 §2: 20주 이동평균 ±20% 밴드로 과열/과매도 판정 + 대응 가격대 제시.

→ 시세 시계열만 있으면(계획서 C단계) **순수 함수로 계산 가능**하다. 사람이 쓸 필요가 없다.
   `lib/quote/envelope.ts` — 20주 MA, 상·하단, 현재 위치(밴드 대비 %).
→ ⚠ "손절 기준선"으로 렌더하지 않는다. 밴드 위치까지만 표시하고 대응은 사람이 쓴다
   (`WOODSMAN_DOCTRINE` — 매매 지시 금지).

### A5. 방법론 한계 고백을 필수 필드로 ⭐
두산 보고서: *"PBR은 수주 모멘텀 기업에 본질적 한계가 있다. 증권사는 EV/EBITDA를 쓰므로 괴리가 난다."*

**자기 방법론을 스스로 부정할 줄 아는 것**이 이 문서에서 가장 강한 대목이었다.
신뢰는 결론이 아니라 한계 고백에서 나온다.

→ 설계서 R6으로 승격. 밸류에이션 섹션에 `limitation` 없으면 발행 차단.
→ 확장 아이디어: **거시·버블 화면에도 같은 필드를 붙인다.** 버블 점수의 한계
  ("정성 지표가 절반이라 채점자 편향이 들어간다")를 화면이 스스로 말하게.

### A6. 같은 질문을 다섯 각도로 다시 묻기
두산 §6: 목표 / 피어평균 / 역사평균 / ROE개선 가정 / 증권사 컨센서스 — **한 숫자를 5번 때린다.**

→ 단일 추정치를 내는 모든 곳에 적용할 수 있는 패턴이다. 버블 점수·인상확률에도 쓸 수 있다.
  (인상확률은 이미 볼트에서 보정형·추정형 probit·시장 선물 **3각도**로 하고 있다 — 같은 사고다.)

### A7. 시계(horizon)를 먼저 밝히고 판정한다
LG이노텍: 중장기(6~12개월) 상승 ✅ / 단기(1~3개월) 조정 ⚠ — 모순이 아니라 **기간이 다른 두 판정**.

→ 판정 필드를 하나로 두면 반드시 뭉개진다. `verdictStructural` + `verdictShort` **두 개**로 나눈다.
  (설계서 §7 저장 모델에 반영함)

### A8. 해자를 "경쟁사 탈락의 역사"로 증명한다
LG이노텍 §1: 오필름(인권 이슈 퇴출) · 샤프(신뢰 상실 → 개발과제 미참여) — 남은 자가 해자를 가진 자다.

→ 해자를 형용사로 쓰지 않고 **사건 목록**으로 쓰는 방식. `StockMoatEvent(연도·경쟁사·사건·결과)`.
→ 이건 AI가 잘 못 만든다(실제 사건 확인이 필요). **사람이 쓰는 자리로 남긴다.**

## 2026-08-11 — 볼트 대시보드 연동에서 나온 것

### B1. 볼트와 사이트가 어긋나는 것을 자동으로 잡는다 ⭐
오늘 버블 지표가 볼트 30개 / 사이트 28개로 벌어져 있었고, **아무 경보도 없었다.**
사람이 대조해야만 알 수 있는 구조는 반드시 다시 벌어진다.

→ 볼트 대시보드의 JSON 아일랜드와 사이트 카탈로그를 대조하는 **점검 스크립트**.
  `site-inspect` 스킬에 "볼트-사이트 카탈로그 대조" 항목을 추가하는 것이 가장 싸다.
→ 대상: 버블 지표 키 집합 · 트리거 수 · 거시 지표 키 집합 · 등급 밴드 경계.

### B2. 개수를 코드에 하드코딩하지 않는다 (교훈)
"28개 지표·7가지 사건"이 화면 4곳에 문자열로 박혀 있었다. 지표를 늘리면 **화면이 조용히 거짓말**을 한다.
→ 오늘 카탈로그 길이에서 읽도록 고쳤다. **같은 병이 다른 곳에도 있는지 훑을 것** —
  "40여 지표"(거시 허브), "5레이어" 같은 문구.

### B3. 볼트 스크립트를 포팅할 때는 회귀 테스트로 묶는다 (교훈)
`fed-hike-prob.py` → `lib/macro/fedhike.ts`를 옮기며 **볼트의 2026-08-11 출력값을 테스트로 못 박았다.**
한쪽만 고치면 테스트가 깨진다. 같은 계산이 두 곳에 사는 모든 경우에 쓸 패턴이다.
