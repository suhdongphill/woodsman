# 바꾼 것과 반응을 잇는다

> 지금은 **바꾼 것**(커밋·배포)과 **반응**(방문·체류·티스토리 클릭)이 **서로 모르는 상태**다.
> 둘을 이으면 "이렇게 바꿨더니 이렇게 됐다"가 남고, 그게 다음 결정의 근거이자 책의 재료가 된다.

---

## 1. 이미 있는 것 / 없는 것

| 있는 것 | 무엇 |
|---|---|
| `PageView` | 경로·날짜별 방문 합계 (⚠ 쿠키·IP를 저장하지 않는다) |
| `PageEngagement` | 체류 구간·스크롤 구간·"읽음" 판정 |
| `OutboundClick` · `OutboundSource` | **티스토리로 넘어간 클릭** — 이 사이트의 1순위 지표 · 어느 화면에서 나갔나 |
| `AdminLog` (2026-08-30) | 관리자가 무엇을 언제 했나 |

| 없는 것 | 왜 필요한가 |
|---|---|
| **변경 시점 마커** | 전후 비교의 기준선. 지금은 배포 시각이 **git에만** 있어 화면이 모른다 |
| **가설** | "무엇을 기대했나"가 없으면 결과를 봐도 해석이 사후 정당화가 된다 |
| **전후 비교 화면** | 사람이 매번 손으로 세면 안 본다 |

---

## 2. `SiteRelease` — 변경을 사이트가 안다

| 칸 | 뜻 |
|---|---|
| `at` | 배포 시각(KST 표시, UTC 저장) |
| `title` | "홈 재편 Step 3 — 첫 화면이 오늘의 바람으로" |
| `kind` | `LAYOUT` · `COPY` · `NAV` · `VISUAL` · `CONTENT` · `FIX` |
| `hypothesis` | ⚠ **기대한 것.** 예: "첫 화면 블로그 CTA로 티스토리 클릭률이 오른다" |
| `metric` | 무엇으로 볼 것인가 — `TISTORY_CTR` · `READ_RATE` · `VIEWS` |
| `commit` | 커밋 해시(개발사·책 원고와 잇는 고리) |

⚠ **가설을 나중에 쓰지 않는다.** 결과를 보고 쓴 가설은 항상 맞는다 — 그건 학습이 아니라 자기기만이다.
배포할 때 같이 쓴다.

---

## 3. 판정 규칙 — ⚠ 표본이 작으면 아무 말도 하지 않는다

이 사이트는 지금 방문이 적다. **적은 표본에서 그럴듯한 결론을 내는 것이 가장 큰 위험**이다.

- 릴리스 **전 14일 vs 후 14일**을 같은 요일 수로 비교한다(요일 효과가 작지 않다).
- ⚠ **최소 표본 미달이면 숫자를 보여 주되 판정을 내지 않는다.** 화면은 "아직 말할 수 없습니다"라고
  적는다 — 빈 칸을 0으로 만들지 않는다는 규칙과 같은 계열이다.
- ⚠ **겹친 릴리스는 분리하지 않는다.** 같은 날 세 가지를 바꿨으면 "이 중 무엇 때문인지 모른다"고
  적는다. 하나만 지목하는 순간 그 문장은 거짓이 된다.
- 외부 요인(검색 유입 급변·시장 이벤트)은 알 수 없다. **인과가 아니라 동시 발생**으로 적는다.

---

## 4. 화면 — `/admin/releases` (⚠ 설계와 달라진 점)

⚠ 처음 설계는 `/admin/analytics`에 겹쳐 그리는 것이었는데, **입력이 있는 화면**이라
별도 라우트로 냈다. 통계 화면은 보는 곳이고 릴리스는 **적는 곳**이라 성격이 다르다.
겹쳐 보기(곡선 위 세로선)는 다음 단계로 남긴다.

- 릴리스 입력 — 무엇을 바꿨나 · 날짜 · 종류 · **가설** · 무엇으로 볼 것인가 · 커밋
- 릴리스마다 **전 14일 / 후 14일 합계**와 판정 한 줄
- ⚠ 화면 맨 위에 **"이 화면이 하지 않는 일"** 을 적어 둔다 — 표본 부족·겹침·인과 아님·자동 변경 없음.
  경고를 각주로 숨기면 아무도 안 읽는다.

---

## 5. ⚠ "스스로 진화"의 경계

사이트가 **스스로 화면을 바꾸지 않는다.** 자동 A/B로 배치를 자율 변경하는 길은 이 사이트에서 택하지 않는다.

- 1순위 목적이 **신뢰**다. 방문자마다 다른 화면을 보여 주면 "공개한 기록"이라는 전제가 흔들린다.
- 표본이 작아 **자동 판정이 거의 항상 틀린다.**
- 대신 사이트는 **근거를 모아 사람 앞에 놓는다.** 결정은 사람이 하고, 그 결정을 다시 릴리스로 남긴다.

> 진화하는 것은 화면이 아니라 **판단의 기록**이다.

## 6. 단계

| # | 무엇 | 공수(세션) |
|---|---|---|
| M1 | `SiteRelease` 스키마 + 관리자 입력(배포할 때 가설과 함께) | 0.5 |
| M2 | `lib/release-effect.ts` — 전후 비교·표본 판정 **순수 함수 + 테스트** | 0.5 |
| M3 | `/admin/analytics`에 릴리스 마커 + 전후 표 | 0.5~1.0 |
| M4 | 지난 릴리스 소급 입력(오늘 것부터) · 개발사에 반영 | 0.3 |
| | **합계** | **1.8~2.3** |

⚠ **M2를 먼저 만든다.** 판정 규칙이 화면 안에 들어가면 "무엇을 근거로 그렇게 말했나"를
테스트로 못 지킨다 — 이 프로젝트가 반복해서 데인 자리다.
