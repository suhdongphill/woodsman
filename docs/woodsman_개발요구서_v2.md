> 6메뉴 IA, 다중 사용자 플랫폼을 전제했다. **실제로 만든 것은 다르다.**
> v1은 발상의 기록으로 남겨 두고, **지금부터의 기준 문서는 이 v2**다.

> 착각이다 — 다음 세션이 틀린 전제 위에서 출발하게 된다(2026-08-29에 실제로 그랬다: §7 참고).

## 0. 무엇을 만들고 있나 (한 문단)

**Woodsman 한 사람이 자기 계좌와 판단을 공개하는 투자 기록 블로그.**
회원가입을 받지 않고, 커뮤니티는 코드만 살려 둔 채 스위치로 잠가 뒀다.
**1순위 목적은 티스토리 블로그로 트래픽을 보내는 것**이고, 성과 지표는 페이지뷰가 아니라
`/admin` 최상단의 **"티스토리로 넘어간 클릭"**이다.

지금 계좌는 **모의 투자(시뮬레이션)**다. 매매·납입은 가상이고 종목 시세는 실제 시장가격이다.
그 사실을 계좌 숫자가 나오는 모든 화면에 밝힌다 — 감추면 나중에 실제 기록을 올려도
신뢰를 회복할 수 없다.

발전 방향: 1인 베타 블로그 → 커뮤니티 개방 → 안정적 파이프라인 관리 지원 서비스 → 법인화.

## 1. v1에서 뒤집힌 결정 (중요)

| v1 구상 | 실제 결정 | 왜 |
|---|---|---|
| Python(FastAPI) 백엔드 + 별도 호스트 | **Next.js 15 App Router 단일 앱** | 서버 컴포넌트로 렌더와 질의를 한 곳에서. 호스트를 하나로 줄임 |
| 관리형 MySQL/Postgres | **Cloudflare D1 (SQLite at edge)** | Workers와 같은 런타임. 개인 규모에 비용·운영 부담 없음 |
| Prisma를 런타임 ORM으로 | ⚠ **Prisma는 스키마·마이그레이션 전용.** 런타임은 D1 바인딩 직접 | Workers 번들에 Prisma 엔진이 안 들어가 첫 쿼리에서 죽었다 (2026-08-02 사고) |
| Cloudflare **Pages** | **Cloudflare Workers** + OpenNext 어댑터 | SSR·미들웨어를 쓰고, Cloudflare도 Workers로 방향을 옮김 |
| 6메뉴 플랫폼(거시분석·투자성향·보고서 등) | **읽는 사이트로 축소** — 홈·인사이트·포트폴리오·투자일지·종목분석 | 가입을 파는 곳이 아니라 읽는 곳. 콘텐츠가 유입을 만든다 |
| 다중 사용자 | **운영자 1인** (가입 잠금) | 커뮤니티는 스위치로 나중에 연다 |

**v1의 미결 질문 5개는 이렇게 정리됐다**: ①②는 위 표대로, ③은 단일 사용자,
④⑤(거시분석·투자성향)는 **범위에서 뺐다** — 지금 사이트의 목적과 맞지 않는다.

⚠ **정정(2026-08-29).** ④ 거시분석은 **다른 모양으로 돌아왔다.** 빼기로 한 것은 v1이 구상한
"사용자별 거시 분석 서비스"였고, 실제로 만든 것은 **읽는 대시보드**다(`/macro`, 지표 53개 ·
버블 모니터 30지표 · P9·P10). 방문자에게 파는 기능이 아니라 **읽을거리**이므로 위 결정과
어긋나지 않는다. 투자성향(⑤)은 여전히 범위 밖이다.

## 3. 되돌리면 안 되는 규칙 (⚠)

전체 목록은 `web/CLAUDE.md` 6장. 특히 자주 깨지는 것:

1. **런타임에 Prisma 금지.** 질의는 `lib/d1.ts`. `getCloudflareContext({async:true})` 필수.
2. **조용한 실패 금지.** 실패 시 안전한 기본값으로 응답하되 **반드시 `console.error`**.
   "값이 없음"과 "읽지 못함"이 같은 화면이 되면 안 된다.
3. **계좌 숫자가 나오는 화면에는 모의/실계좌 표시**(`DataModeNotice`). 기본값은 모의.
4. **통화가 섞인 값을 그냥 더하지 않는다.** `allocation.holdingValueKrw()`로 원화 환산 후 계산.
5. **날짜만 있는 값은 정오(UTC) 저장.** 자정으로 넣으면 화면에서 하루 밀린다.
6. **AI 키는 DB에 저장하지 않는다.** `.env` → `npm run ai:sync` 한 경로뿐.
7. **AI 프롬프트에 Woodsman 공통 규범이 항상 맨 앞.** 매수 권유·목표주가·방향 단정 금지.
8. **유료 AI 제공자에 월 토큰 상한 필수.** 제한 시간도 필수.
9. **DB 정책을 읽는 페이지에 `generateStaticParams` 금지** — `force-dynamic`.
10. **가입은 항상 USER.** ADMIN은 시드/스크립트로만.

### 자동 수집 — Cron Trigger (2026-09-01)

⚠ 그 전까지 **모든 지표 수집이 관리자 버튼 하나뿐**이었다. 사람이 안 누르면 모든 지표가
조용히 낡는다(8/31에 환율이 열흘 뒤처진 값으로 화면에 떠 있었다).

- **매일 06:00 KST**(`0 21 * * *` UTC)에 거시 지표 + 종목 시세를 함께 받는다.
- 진입점은 `web/worker.js`다. ⚠ **`main`이 `.open-next/worker.js`가 아니다** —
  OpenNext가 만드는 파일에는 `fetch`만 있어 Cron을 받을 수 없어서, 그것을 감싸는 파일을
  두고 `scheduled`를 얹었다. Durable Object 셋을 다시 export 해야 배포가 산다.
- 수집 자체는 **관리자 버튼과 같은 함수**가 한다(`ingestMacro`·`ingestQuotes`).
  자동 실행은 이력에 `trigger: "CRON"`으로 쌓이고 `/admin/macro`가 「자동/수동」으로 보여준다.
- ⚠ 시크릿 `CRON_SECRET`(32자 이상)이 **필요하다**. 없으면 스케줄이 돌아도 아무것도 하지
  않고 로그에만 남는다 — 설정 누락이 "누구나 통과"가 되면 안 되기 때문이다.

⚠ **`secret put`을 쓰지 않는다** (2026-09-08에 바뀐 지침). 대화형 프롬프트도, stdin 파이프도
값을 못 받은 채 **에러 없이 끝날 수 있다.** 실제로 9/5에 그렇게 들어가 `CRON_SECRET`이
**이름만 등록되고 값이 비었고**, 사흘간 스케줄이 한 번도 돌지 않았다.
⚠ 더 나쁜 것은 **`wrangler secret list`도 `versions view`도 이름만 보여 주므로 둘 다
「있다」고 답한다는 것**이다. 그 사고는 이름을 보는 도구로는 잡히지 않는다.

```bash
# 값을 JSON 파일에 담아 넣는다 — stdin을 쓰지 않고, 성공을 말로 한다.
node -e "const fs=require('fs'),c=require('crypto');fs.writeFileSync('s.json',JSON.stringify({CRON_SECRET:c.randomBytes(32).toString('hex')}))"
cd web && npx wrangler secret bulk ../s.json --name woodsman
#   → "✨ 1 secrets successfully created" 가 떠야 들어간 것이다
rm s.json
```

⚠ **넣었으면 화면으로 확인한다.** `/admin/macro`의 「자동 수집」이 `시크릿: 등록됨`으로
바뀌어야 한다. 여기가 **값을 실제로 읽어 보는 유일한 자리**다(`cronSecretState`).

  ⚠ **2026-09-13: 이 규칙을 코드로 옮겼다.** 글에만 있던 동안 전사 화면은 수동 지표 전부를

  찾아 붙이게 만들면 결국 아무도 안 넣는다(수동 일곱 개가 비어 있던 이유다).

### 정책금리 — 처방과 시장 기대를 **따로** 낸다 (2026-09-13)

같은 질문("금리가 어디로 가나")에 답이 둘이고, 둘은 다른 숫자다. 한 카드에 뭉개지 않는다.

| 무엇 | 모듈 | 답하는 것 |
|---|---|---|
| `fedhike` | Taylor(1993) + CGG(2000) | **모형이 처방하는 것** |
| `fedfutures` | 연방기금 선물 `ZQ=F` | **사람들이 돈으로 거는 것** |

- ⚠ **CME 페드워치를 가져오지 않는다.** CmeWS는 403이고 응답이 "scraping은 이용약관 위반"
  이라고 직접 말한다(2026-09-13 재확인). 원재료(Yahoo `ZQ=F`)에서 **우리가 계산**하고,
  화면에 「우리 계산」이라 적는다. 페드워치와 소수점이 다를 수 있다.
- ⚠ **근월물 선물은 계약월을 확인하지 않으면 쓸 수 없다.** 달이 바뀌면 다른 계약이고,
  Yahoo는 이름을 31자에서 잘라 계약월을 **두 글자**만 준다(`…Futures,Oc`). 두 글자로 가릴 수
  있는 것은 「근월물은 이번 달이나 다음 달」이라는 제약 덕분이고, 겹치는 달은 **6월뿐**이다.
- ⚠ **계약월을 DB에 적지 않는다. 대신 수집이 불변식을 지킨다** — 「시세일의 다음 달 계약」이
  아니면 저장하지 않는다(`MacroPoint`에 적을 자리가 없어 컬럼을 늘리는 대신 택한 길이다).
  Yahoo가 롤 시점을 바꾸면 지표가 **멈추고 `MacroIngest.detail`이 이유를 문장으로 남긴다.**
- ⚠ **가정의 크기를 화면에 적는다.** 계약 하나로는 회의 전·후 금리를 함께 풀 수 없어
  계약월 안의 회의는 「변화 없음」으로 둔다. 그 가정이 걸린 날수 비중을 같이 보여준다.
- ⚠ **변환은 한 곳에만 둔다.** 가격→금리(100 − 가격)는 표시 변환 `price100`이 하고,
  `fedfutures`는 이미 변환된 금리를 받는다.
- 회의일은 **캘린더(`MacroEvent`)**에서 온다. 제목에 「FOMC」가 없으면 못 찾고, 그때는
  **계산하지 않는다**(카드가 안 나온다). 자동 출처가 아닌 자리라 캘린더가 곧 입력이다.

### 자본 엔진 — 수요 축소인가 공급 확대인가 (2026-09-13)

상위 거시 화면. 「AI 자본지출이 물가를 올리는가, 생산성이 그걸 흡수하는가」를 데이터로 좇는다.
⚠ 한 방향을 미리 정답으로 두지 않는다 — 경쟁가설 H1~H5를 **동시에** 놓고 본다.
전체 가용성 판정은 `docs/분석_자본엔진_가용성_2026-09-13.md`.

- ⚠ **스택을 늘리지 않는다.** 요구 초안은 FastAPI·Postgres·Redis·Celery를 권했지만, 이 사이트는
  Workers + D1이고 「불필요한 별도 애플리케이션을 만들지 않는다」가 같은 초안의 마지막 줄이다.
  **판단이 두 곳에 생기는 것**이 이 저장소가 가장 크게 데인 사고다. 스코어링은 `lib/macro/*`
  순수 함수 + vitest, 스케줄은 Cloudflare Cron을 그대로 쓴다.
- ⚠ **점수(score)부터 만들지 않는다.** 원자료 → 관계 → 점수 → 종합 순서다. 원자료가 없는
  종합점수는 **그럴듯한 숫자를 만들어 낸다.** 원자료가 다 있는 축만 점수를 만들고, 빈 축은
  「못 받는다」고 적어 둔다.
- ⚠ **투자(CAPEX)를 생산성으로 계산하지 않는다.** 돈을 쓴 것과 산출이 는 것은 다른 숫자다.

#### 「생산성·공급」 묶음 · 미래 관측점 차단 (2026-09-14)

- 묶음 `supply`(`/macro/supply`) — 노동생산성 `prod_yoy` · 단위노동비용 `ulc_yoy` · 실질 시간당 보수
  `real_comp_yoy`(COMPRNFB) · 잠재산출 `pot_gdp_yoy`(GDPPOT). 질문은 「수요를 죽이지 않고 물가를 잡을 수 있나?」.
  ⚠ 「생산·제조」는 「경기가 좋은가」라 **섞지 않는다.** 명목 GDP(`ngdp_yoy`)는 산출 규모라 「생산·제조」에 남는다.
- ⚠ **지표를 묶음 사이에서 옮길 때 `key`를 바꾸지 않는다.** 묶음은 카탈로그에만 있고 D1은 `key`로 쌓인다.
- ⚠ **관측일이 미래인 점은 관측이 아니다**(`lib/macro/observed.ts`). 수집기 입구의 일반 규칙이고, 버린 수는
  `MacroIngest.detail.droppedFuture`로 남아 `/admin/macro` 이력에 보인다. GDPPOT은 2036년까지 값이 있어
  이 규칙이 없으면 화면이 「2036-10-01 기준」이라고 말한다(실측: 41점을 버리고 2026-07-01에서 멈춘다).
- ⚠ 추계 계열은 **추정치라고 스스로 말한다**(`sourceLabel`·`what`). 확인 안 된 원 발표 기관 링크(CBO)는
  걸지 않고 이름만 댄다.

#### 신뢰 계층 — `claims.ts` · `glossary.ts`

우리가 만든 지표는 근거 없이는 장식이다. 그래서 **숫자보다 믿을 이유를 먼저** 짓는다.

- ⚠ **`Fact`는 1차 출처 URL과 확인일 없이 존재할 수 없다.** 테스트가 강제한다. 출처 없는
  「사실」이 하나라도 섞이면 등급 체계 전체가 장식이 되고, 독자는 우리가 확인했는지 알 방법이 없다.
- ⚠ **확인한 링크만 싣는다.** 죽은 1차 출처 링크는 **없는 것보다 나쁘다.** 그리고 **봇 차단(403)과
  죽은 링크는 다르다** — 403이면 본문을 받아 살아 있는지 본다. 그렇게도 확인 안 되면 **싣지 않는다.**
- ⚠ **원 발표 기관을 댄다.** FRED는 배급처다. 생산성은 BLS, GDP는 BEA, 금리는 재무부다.
- ⭐ **우리가 만든 이름은 우리 것이라고 말한다**(`own: true`). `PRYS`·`성장–조달 격차`는
  표준 지표가 아니다. `^MOVE`를 MOVE라 부르지 않기로 한 것과 같은 규범이다.
- ⚠ **`Rejected`를 지우지 않고 적어 둔다.** 「연준이 장기금리를 직접 통제한다」처럼 그럴듯해서
  재등장하는 문장은, 안 쓰기로만 하면 다음 사람이 또 쓴다.

##### 본문에서 누르게 — `/macro/glossary` · `<Term>` (2026-09-14)

- 사전은 `/macro/glossary` 한 페이지이고, 용어마다 **앵커 `slug`**가 있다(`#prys`).
  ⚠ **`slug`는 바꾸지 않는다** — 발행 글이 그 주소로 링크한다.
- 본문의 용어는 `features/macro/ui/Term.tsx`로 건다. ⚠ **클라이언트 JS 없이**(점선 밑줄 +
  `title` + 링크). 사전에 없는 말이면 링크 없이 글자만 두고 `console.error`를 남긴다.
- 사전 페이지는 약속 셋을 화면에 적고, 우리 정의는 제목 옆에서 「표준 지표 아님」을 먼저 말한다.
  구조화 데이터는 `DefinedTermSet`(용어마다 앵커 URL).
- ⚠ sitemap에는 **lastmod 없이** 들어간다(코드 상수라 바뀐 날을 모른다).
- 새 용어를 넣는 순서: **링크 확인 → `checked`·`checkMethod` 기록 → `slug` 부여 → 화면에서 `<Term>`.**

#### ⭐ 연준의 책무는 **셋**이다 (제2A조)

법은 「최대 고용 · 물가 안정 · **적정한 장기금리**」를 적었고, 통화·신용 총량을 「경제의 **장기
생산 잠재력에 상응하게**」 유지하라고 적었다. ⚠ 「장기금리 관리는 숨은 책무」라는 흔한 말은
**틀렸다 — 숨어 있지 않고 쓰여 있다.** 숨은 것은 「어떻게」이지 「무엇을」이 아니다.
⚠ 다만 **연준이 10년물을 특정 수준으로 겨냥한다는 것은 사실이 아니다**(`Rejected`).

#### 설명글에 조망을 담는다

지표의 `what`/`why`/`read`를 「이게 뭔가」에서 끝내지 않고 **「이 숫자가 움직이면 수요 축소 쪽과
공급 확대 쪽 중 어느 힘이 세지는가」**까지 적는다. ⚠ 다만 `read`가 **읽는 법까지만** 쓴다는 선은
그대로다 — 매매 판단으로 넘어가지 않는다.

### Capital Regime Engine — 자본 엔진의 다음 단계 (2026-09-13 설계 착수 · v0.1)

⭐ **상세 설계는 `docs/설계_자본레짐엔진.md`에 있다.** 여기에는 **지금 유효한 원칙과 상태**만 적는다.
원문은 ChatGPT가 작성한 요구 프롬프트(PART I~XXXI)이고, ⚠ **PART XXXI 중간에서 끊겨 있다.**

- ⭐ **경제관은 이미 지은 것과 같은 방향이다** — 「금리가 높은가」가 아니라 「성장·생산성·이익이 이 금리를

### 금리·거시(rates) 섹션 — 계산은 파이썬, 화면은 사이트 (2026-09-05)

- `pms rates`(파이썬 CLI)가 FRED·ECOS를 수집·계산·검증하고 `web/public/data/rates.json`으로
  내보낸다. 사이트의 `/macro/rates`는 **그 파일 하나만** 읽는다.
  ⚠ 프런트에서 외부 API를 직접 부르지 않는다 — 같은 숫자가 두 경로로 들어오면 어느 쪽이 맞는지
  아무도 모르게 된다.
- ⚠ **계열 ID는 `config/rates_series.yaml`이 유일한 목록**이고 `pms rates verify`가 실제 API로
  대조한다. 화면보다 이 검증이 먼저다 — 틀린 ID로 화면을 만들면 잘못된 숫자에 디자인이 굳는다.
- ⚠ **파생 지표는 `inputs_json`으로 입력 계열·관측일·값을 남긴다.** 비면 저장을 거부한다.
- ⚠ **결측은 `null`이고 화면은 선을 끊는다.** 미발표를 0으로 채우지 않는다.
- ⚠ **r*가 없으면 「정책 제약도」 레이어를 산출하지 않고** 가중치를 재정규화한 뒤 「부분 산출」로
  표시한다. 중립금리를 임의로 가정하면 지수 전체가 그 가정 위에 선다.
  ⚠ **r*는 실질값이다** — 계산이 `real_policy − neutral_rate`다. FOMC SEP의 장기 중앙값은
  명목이므로 목표 2%를 빼야 하고, **그 변환도 가정**이다(2026-09-07 확인).
- ⚠ **`/macro`와 `/macro/rates`는 다른 시스템이고, 계열을 양쪽에 두지 않는다.**
  `/macro`는 사이트 지표(D1 `MacroPoint`), `/macro/rates`는 파이썬 파이프라인(`rates.json`)이다.
  **같은 계열을 양쪽에 등록하면 같은 숫자가 두 경로로 들어온다** — 위의 「프런트에서 외부 API를
  직접 부르지 않는다」와 같은 이유로 금지한다. 금리·물가·유동성 계열이 필요하면
  **rates 쪽에 세우고 `/macro`에서 링크한다**(사용자 요청 검토, 2026-09-07).
- **발표본(vintage)은 ALFRED로 받는다** — `pms rates vintages`, 테이블 `rates_vintage`.
  ⚠ FRED가 주는 것은 **지금의 값**이고, 「그때 무엇이라고 발표했나」는 그 값으로 답할 수 없다.
  ⚠ 증감은 **같은 발표본 안에서** 잰다(두 발표본을 섞으면 발표된 적 없는 숫자가 나온다).
  ⚠ 「수정 0」과 「아직 개정될 기회가 없었다」를 구분한다. 그리고 **개정된 값을 틀린 값이라고
  적지 않는다** — 둘 다 그때의 최선이다(2026-09-07).
- **지표 카드는 `id` 앵커를 갖는다** — `/macro/rates#dgs30`. 글이 지표를 문장 단위로 가리키는

- **내보내는 기간은 7년(84개월)이고 `meta.history_months`로 함께 나간다.** 그보다 긴 역사는
  계열마다 원출처(FRED·ECOS) 링크로 넘긴다 — 긴 역사는 원출처가 우리보다 잘 보여준다.
  ⚠ 파일 크기 때문이 아니다(977KB도 gzip 198KB였다). **어디까지 우리가 그릴 일인가**의

   동작하지만 **Zone 범위 권한을 가질 수 없다.** `wrangler.jsonc`가 커스텀 도메인 두 개를
   선언하고 있어 배포는 매번 그 영역의 Workers Routes를 확인한다.
   **사용자 소유 토큰**(My Profile → API Tokens)으로 바꾸고 D1:Edit를 더해 뚫었다.

⚠ **시크릿은 넣은 뒤 다시 읽을 수 없다.** 그래서 추측이 반복됐다. 러너에게 직접 묻는
일회용 워크플로(값 대신 sha256 앞 8자리를 찍고, 실패하는 호출을 러너에서 그대로 때린다)를
만들고 나서야 한 번에 좁혀졌다. 같은 상황이 또 오면 커밋 `96a1c53`을 되돌려 쓰면 된다.

⚠ 그래도 **배포 후에는 운영본을 직접 열어 확인한다.** 로컬 통과는 배포 성공이 아니다.

### 콘텐츠 관리 화면은 **셋으로 나뉘어 있다** (2026-08-30)

`/admin/posts`(목록) · `/admin/posts/new`(새 글) · `/admin/posts/edit?id=…`(수정).

⚠ **목록에 편집기를 다시 얹지 않는다.** 한 화면에 있던 시절, 목록만 보려는 사람도 편집기의
미리보기 변환기를 클라이언트로 다 받아야 했고 **그 JS가 붙기 전에 누른 「편집」이 삼켜졌다.**
운영자는 "편집이 안 된다"고 판단해 같은 글을 새로 써서 저장했다 — 중복 글의 원인이었다.

⚠ 글 id는 **경로가 아니라 질의(`?id=`)로** 받는다. id에 `:`와 `.`이 들어 있다.

⚠ 주소(slug)는 **제목에서 자동으로 만든다**(`lib/slug`). 이미 있는 글은 **잠근 채로 시작한다** —
발행된 주소가 제목을 따라 바뀌면 밖의 링크와 색인이 깨진다. 충돌은 막지 않고 **비켜 가고 알린다.**

### 홈은 콘텐츠로 열고, 계좌는 그 답이다 (2026-08-30~31, Step 1~6 완료)

홈 라우트는 **조립만 한다**(400줄 → 130줄대). 블록은 `features/home/ui/*`,
"어떤 블록을 어떤 순서로 그릴지"는 `lib/home-layout.ts`(순수 함수 + 테스트)가 정한다.

지금의 순서 — ⚠ **`HOME_BLOCKS` 배열이 정한다.** 라우트가 JSX로 나열하지 않는다
(나열하면 배열과 화면이 어긋나고, 그걸 지킨다던 테스트가 자기 자신을 검사하게 된다):

> 히어로(거시 한 줄) → **거시 스트립** → **최신 인사이트 + 티스토리 CTA** → 홈 글 →
> 거시 보드 → **계좌 띠** → 투자일지 · 종목 보고서 → 운영 원칙

⚠ **콘텐츠가 맨 앞이다.** 1순위 목적이 블로그 유입인데, 전에는 방문자가 거시 보드와
원칙 3장을 지나야 티스토리 링크를 만났다. ⚠ **「어떻게 기록하나요」는 맨 뒤다** —
소개글이지 콘텐츠가 아니다.

⚠ **계좌는 입구가 아니라 증거다**(Step 2). 첫 화면의 계좌 카드를 콘텐츠 뒤의 한 줄 띠
(`AccountStrip`)로 내렸다. **지우지는 않았다** — 운영지침 §4와 부딪히는 판단이라 사람이 정했고,
§4에 그 뜻을 정정해 적었다(자리가 아니라 존재를 지킨다).

⚠ 자금 흐름 차트는 홈에 없다 — `/portfolio`에만 있다. `design-policy.test.ts`가
**쓰는 라우트가 하나뿐인지** 세어 중복을 막는다.

#### `/portfolio`는 「흐름에 대한 나의 답」이다 (Step 4, 2026-08-31)

머리말이 그렇게 말하고, 화면 위에 **「지금 부는 바람 …」 한 줄 + `/macro`로 가는 링크**가
붙는다(`MacroAnswerNote`). `/stocks`의 주도주 표가 「그래서 내 배분은 →」으로 여기를
가리키므로 고리가 닫힌다. ⚠ 거시 값이 없으면 그 줄은 **사라진다**(지어내지 않는다).

#### 검색·AI가 읽는 문장 (Step 5, 2026-08-31)

⚠ 사이트 자기소개는 **`lib/site-identity.ts` 한 곳**에서만 정한다 — 메타·`llms.txt`·
홈 JSON-LD가 같은 상수를 읽는다. 화면은 눈에 보이니 고쳐지고 이 문장들은 안 보이니
안 고쳐진다(두 번 데였다). 홈에는 `WebSite` JSON-LD가 붙는다.
⚠ **기계가 읽는 자리**엔 별표 0개(`stripEmphasis`), **화면**은 `Emphasis`로 굵게.

⚠ 계좌 숫자가 한 줄이라도 나오면 **모의/실계좌 표시는 의무**다. 자리가 줄어도 따라간다.
⚠ 홈의 계좌 띠도 `/portfolio`의 자금흐름도, 값이 없으면 **없다고 적는다** — 섹션을 지우지 않는다.
⚠ **판단과 문구를 라우트에 다시 넣지 않는다.** 넣는 순간 화면을 띄워야만 확인되는 규칙이
다시 생긴다. 단계별 기록은 `docs/설계_홈_콘텐츠중심_재편.md`에 있다.

#### ⭐ 운영자 원칙 — 첫 화면의 숫자 · 판정의 자리 · 콘텐츠의 뼈대 (2026-09-14 사용자 결정)

> ⚠ 운영자(Woodsman)가 준 관점은 **여기에 원칙으로 적는다.** 코드에만 반영하면 다음 결정이
> 그 원칙을 모른 채 반대로 난다. 원칙이 기존 설계와 부딪히면 먼저 말하고 사람이 정한다.

**① 첫 화면의 숫자는 뜻과 함께 낸다.**
- 첫 화면 버튼 아래 「추적 중인 지표 72개 · 계좌 기록 준비 중 · 공개 방식 모의 투자」를 걷었다.
  떨어진 「72개」는 **무엇을 추적하는지 말하지 못한다.** 기록 셋(개월·일지·리밸런싱)은 기록이
  생기면 다시 뜬다.
- 지표 수는 **묶음과 함께** 말한다 — `/macro` 머리말·묶음 목록, 홈 거시 섹션에
  「N개 묶음 · 지표 M개」, 묶음 카드마다 「지표 N개」.
- ⚠ **개수는 화면이 센다** — 전체는 `MacroOverview.indicatorCount`(카탈로그 전체), 카드별은 `total`(묶음 전체).
  손으로 적은 「아홉 개 묶음」이 11개가 된 뒤에도 남아 있었다.
- ⚠ **보이는 수와 전체 수를 섞지 않는다.** 묶음 카드는 대표 3개만 싣는다(`items`). 처음에 그걸 세어
  「지표 33개」(11×3)라고 적을 뻔했다 — 실제 72개. 테스트는 통과했고 **화면을 띄워서야** 보였다.
  그래서 카드는 「지표 14개 · 대표 3개만 표시」처럼 **둘 다** 적는다.

**② 좋은 판정은 뒤에 숨기지 않는다.**
- 침체 신호 종합 · AI 버블 점수 · 유동성 판정은 이 포털의 진가다. 그런데 `/macro` 안쪽과 하위
  페이지(`/macro/bubble`·`/macro/liquidity`)에 있어 **처음 온 손님은 그 존재를 모른다.**
  홈·허브의 **앞줄**로 끌어낸다.
- ⚠ **지금 점수로 있는 것과 없는 것이 갈린다.** 침체 신호(5개 종합)와 버블 점수
  (`lib/bubble/score.ts`)는 있다. **유동성은 원자료(순유동성 `netliq`·TGA `tga`)만 있고 판정
  점수가 없다.** 앞줄에 올리려면 판정을 먼저 만든다 — 자리부터 만들고 점수를 채우지 않는다
  (자본 엔진의 「점수부터 만들지 않는다」와 같은 원칙이다).
- ⚠ 앞줄에서도 **기준일 · 결측(몇 개 중 몇 개로 채점했나)**을 같이 낸다. 요약할수록 이게 먼저 빠진다.
- ⚠ 1순위 목적(티스토리 유입)과 자리가 부딪히면 **CTA가 우선한다.** 판정 앞줄이 CTA를 밀어내지 않는다.

**③ 콘텐츠의 뼈대는 「조류의 흐름」이다 — 지정학 리스크 → 유가 → 금리 → 시장 변동성.**
- 유가는 지정학 리스크로 움직인다. 그러므로 **본질은 지정학 리스크**이고, 유가·금리·변동성은
  그 충격이 번지는 경로다. 지표 화면이 「지금 어떤가」를 말한다면 이 뼈대는 「왜 그렇게 됐나」를 말한다.
- 담을 것: 지정학 주요 이슈 · 시장에 큰 충격을 준 금리·환율 사건 · 정책 충격(예: 트럼프 「TACO」
  — 발표 뒤 물러서는 패턴을 가리키는 시장 속어)을 **주요 글로벌 기사**로.
- ⚠ 기존 규범을 그대로 적용한다:
  - 기사·사건은 **1차 출처 · 날짜**와 함께. ⚠ 「TACO」 같은 속어는 **처음 쓴 매체를 확인해** 용어 사전
    규칙대로 붙인다 — 확인 전에는 출처를 적지 않는다.
  - 고리마다 등급을 단다(`lib/macro/claims.ts`의 Fact / Inference / Hypothesis / Rejected).
    「지정학 사건 → 유가」는 관측이어도 「→ 금리 → 변동성」까지 한 번에 인과로 쓰지 않는다.
  - 「같이 움직였다」와 「원인이다」를 구분한다(겹쳐 보기 화면의 선 그대로).
  - 지정학은 숫자 계열이 약하다. **사건 기록(날짜·사건·출처)과 지표(유가·금리·VIX·달러)를 같은
    시간축에 잇는 형태**가 된다 — 사건을 점수로 바꾸지 않는다.

### 관리자 활동 로그 (2026-08-30)

`/admin/logs`. 콘텐츠(작성·수정·삭제) · 거시 자료 가져오기 · 사이트 기본값을 기록한다.

⚠ **아직 기록하지 않는 자리를 화면이 그대로 적는다.** 부분만 기록하는 로그의 가장 큰 위험은
**없는 것을 "안 한 것"으로 읽는 것**이다.
⚠ **기록이 하던 일을 막지 않는다.** 로그 쓰기 실패는 삼키되 `console.error`로 남긴다.
⚠ 시각은 **KST로 보여 준다**(`seoulDay`·`seoulTime`). UTC로 보여 주면 밤에 한 일이
어제 일로 보인다.
⚠ **보관 정책은 아직 없다** — 무한히 쌓인다. D1 크기는 `/admin/diagnostics`가 본다.

### ⚠ 개발 서버의 관리자 화면 CSP (2026-08-30)

관리자 엄격판 CSP는 `'unsafe-eval'`을 막는데 **Next 개발 모드의 리프레시 런타임이 eval을 쓴다.**
막힌 동안 **로컬 `/admin/*`은 클라이언트 JS가 통째로 안 살아났다**(화면은 그려지는데 아무것도
안 먹는다). 지금은 **개발에서만** 예외를 연다 — ⚠ **운영 CSP는 그대로 조여 둔다.**
