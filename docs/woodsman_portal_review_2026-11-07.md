# 1. 결론

- **Gemini 안은 채택하지 않는 것이 맞습니다.** 핵심 해법이 "목업 데이터(mock data)로 완성된 것처럼 보이게 하기"입니다. 이 방식은 사이트 스스로 밝힌 고지문(모의 투자)과 충돌합니다. Google 게시자 정책의 "콘텐츠 자체를 잘못 표현(misrepresents … the content itself)" 조항에도 걸릴 수 있습니다. 예시로 든 주제 셋 중 두 개는 사실관계가 틀렸거나 낡았습니다.
- **OpenAI 안은 방향이 맞습니다.** 실데이터와 가상 사례를 구분하고, 결측을 0이나 '정상'으로 바꾸지 않고, 심사 봇 전용 분기를 금지합니다. 관찰 사항도 대부분 실제와 일치합니다. 다만 일부 항목은 이미 해결돼 있고, 한 항목은 사실과 어긋납니다.
- **두 안 모두 가장 큰 위험 요인을 놓쳤습니다.**
  - /macro·/insights 등에 걸린 **"BETA · 개발 중인 베타 사이트입니다"** 배너
  - **/macro 하위 페이지 데이터가 9월 말에서 멈춘 것**: 홈은 11/4 기준, /macro는 9/24 기준
  - 9/20 이후 **신규 인사이트 글 없음**
  - **푸터·소개("운용 중인 계좌")와 고지문("모의 투자")의 정면 충돌**

AdSense 도움말이 직접 꼽는 거절 사유는 "공사 중(under construction)" 사이트입니다. 빈 칸을 가짜 숫자로 채우는 것보다 이 배너와 멈춘 데이터를 정리하는 쪽이 효과가 큽니다.

# 4. 두 AI가 모두 놓친 것

1. **"BETA · 개발 중인 베타 사이트입니다" 배너** (/macro, /macro/rates, /insights). AdSense 거절 사유 원문인 "pages under construction or not yet launched"에 가장 직접 걸리는 요소입니다. 정식 운영 중이면 배너를 내리고, 실험 기능만 개별 카드에 '실험 지표'로 표시하세요.
2. **/macro 데이터가 9월 말에 멈춤.** 홈은 10년물 4.90%(11/4)인데 /macro·/macro/rates는 5.18%(9/24)입니다. 침체 신호도 9/26 기준이고 /macro 하위 페이지 22개가 sitemap에 올라 있습니다. 문구 정리보다 **갱신 파이프라인 점검**이 먼저입니다.
3. **같은 페이지 안의 숫자 불일치.** /macro 상단 타일은 순유동성 5.80조·TGA 0.95조, 아래 카드는 5.77조·0.98조입니다. 지표 개수도 홈 116개, /macro 115개로 다릅니다. ISM PMI 배지는 홈에서 '기한초과', /macro에서 '정상'입니다.
4. **공개 화면에 남은 개발 흔적.**
   - "docs/금리섹션_지표해설.md가 단일 출처입니다" (/macro/rates, 내부 저장소 파일명)
   - "⚠ 부분 산출 — policy_stance 레이어가 빠졌습니다" (변수명 노출)
   - "⚠ 투입값 기준일이 176일 벌어져 있습니다"
   - 경고 자체는 정직해서 좋습니다. 표현만 독자용으로 바꾸세요. 예: "정책 기조 요소는 아직 반영하지 않았습니다 · 반영 전 산출치".
5. **콘텐츠 신선도.** 인사이트 최신 글이 9/20입니다. 7주 동안 새 글이 없으면 '방치된 사이트'로 보입니다. 이미 쓴 크립토 자본경로 글(9/27)이나 기업분석 글을 포털에 올리는 것이 목업보다 훨씬 강한 신호입니다.
6. **티스토리와 포털의 중복 콘텐츠.** 같은 글을 두 사이트에 그대로 올리면 검색에서 중복 문서로 처리될 수 있습니다. 포털판은 데이터 카드와 지표 링크를 붙인 '데이터 판'으로 차별화하세요. 그렇게 할 수 없으면 원문 쪽을 canonical로 지정하세요.
7. **준법 확인이 필요한 부분.** 푸터와 소개대로 '실제 계좌 성과 공개'라면, 은행 임직원의 금융투자상품 매매·외부 활동에 관한 내부 규정에 맞는지 준법감시 부서에 확인해 두는 것이 안전합니다. 광고 수익이 붙는 투자 판단 공개가 유사투자자문업 신고 대상인지도 같이 확인하세요. 저는 적용 여부를 판단할 수 없습니다. 모의 투자로 통일하면 이 위험은 대부분 줄어듭니다.

## P1-1. 데이터 갱신과 정합성
- 홈 10년물 4.90%(2026-11-04)인데 /macro·/macro/rates는 5.18%(2026-09-24), 침체 신호 기준일도 홈 11-07 vs /macro 09-26.
  /macro 하위 페이지가 정적 생성 후 갱신되지 않는지, 캐시·빌드·크론을 점검하고 원인을 보고하세요.
- 같은 페이지 불일치: /macro 타일 순유동성 5.80조·TGA 0.95조 vs 카드 5.77조·0.98조. 지표 개수 홈 116 vs /macro 115.
  ISM PMI 배지가 홈 '기한초과', /macro '정상'. 지표별 단일 출처·단일 상태 계산 함수로 통일.
- 리밸런싱 횟수: /portfolio "총 1회(2026-10-26)" vs /journal "리밸런싱 0회". 집계 원천을 하나로.

## P1-2. 공통 상태 모델
- 상태: 정상 / 발표 주기상 정상 지연 / 이전 유효값 사용 / 갱신 지연 / 값 미제공 / 비교 이력 부족 / 산출 기준 미충족 / 조회 실패 / 비적용.
- 표시 예: "최근 확인값 · YYYY.MM.DD 기준", "갱신 지연 · YYYY.MM.DD 기준", "추세 비교 자료 부족", "자료 미제공", "데이터를 불러오지 못했습니다".
- 갱신 일정이 실제로 없으면 '업데이트 예정'이라고 쓰지 말 것. 기준일을 실제보다 최근으로 표기하지 말 것.
- 데이터 기준일·수집일·계산일을 구분. 월간·분기 지표의 정상 발표 지연(예: 월간 지표의 다음 달 발표)을 오류로 처리하지 말 것.
- null/undefined/NaN/Infinity/잘못된 날짜/빈 배열 방어. 결측을 0·보합·정상으로 변환 금지. 배지 줄바꿈·모바일 점검.

## P1-3. 요약 문장과 판정 일치
- 홈 침체 요약 "5개 지표가 모두 기준선 안쪽입니다"가 기한을 넘긴 ISM 값(2026-08-01)을 그대로 세고 있음.
  요약 문장을 판정 데이터에서 생성하고, 지연·결측 입력이 있으면 "1개 지표는 지연된 값 기준"처럼 영향 표시.
- VIX가 5개 침체 지표에 포함되는지 확인하고, 별개 체계면 카드 근처에 차이 설명.
- GCRM '엔진 온도 72(평소보다 크게 높다)'와 포털 '경기 엔진 온도 53(평소 수준)'은 다른 모델로 보임.
  유동성에는 이미 있는 "다른 모델입니다" 설명을 엔진 온도에도 추가. 두 점수를 합치지 말 것.

## P2-1. /portfolio
- 현재 상태: 100종목, 구성 65.6%, 성장 84.4% / 인컴 13.1% / 방어 2.5% (목표 50/30/20).
- 50/30/20은 '목표'로 표시하고, 현재 배분을 목표에 맞춘 숫자로 바꾸지 말 것. 기존 종목을 임의 ETF로 교체 금지.
- 스냅숏 0개: 빈 차트 대신 목표 배분·현재 확인 가능한 배분·목표 대비 편차·자산별 역할·리밸런싱 원칙.
  스냅숏 1개: '현재 구성 카드'. 추이는 2개 이상 이력이 있을 때만. 과거 곡선 생성 금지.

- '구성 완료 65.6%'의 산식 확인. 이해하기 어려우면 목표 대비 편차로 대체.
- 종목 카드 반복 "목표비중—"은 생략하거나 "개별 목표 미설정"을 한 번만 설명.

## P2-2. 투자일지
- 공개 가능한 실제 판단 기록이 저장소/DB에 있는지 먼저 확인하고, 있으면 최신 3~4개 표시.

- 교육용 사례를 추가할 경우 투자일지와 분리된 경로(/cases 등)에 두고, 카드·본문에 '교육용 가상 사례'를 명시.
  작성일과 분석 대상 시점을 구분하고, 시장 수치는 출처·기준일 검증된 것만 사용.

## P2-3. 콘텐츠와 검색
