# 시장 관찰 포털 — 통합 작업 계획

## 0. 목표 한 줄

> **포털은 시장을 계속 관찰하고, 독자에게 독특한 정보를 전달한다.**
> 독특함은 세 가지에서 나온다 — ① **우리가 계산한 판정**(산식 공개 · LLM이 점수를 정하지 않음) ② **조류·바람·파도로 나눈 읽기**
> ③ **나무꾼이 그 속에서 실제로 어떻게 하는지**(계좌·일지 · 산장).

## 1. 이번에 받은 요구를 목표에 붙인다

| 요구(2026-09-14) | 목표의 어디 | 조각 |
|---|---|---|
| ChatGPT는 유동성 점수를 내는데 우리는 판정 보류 — 산출 방법을 찾아라 | ① 우리가 계산한 판정 | **S1** 전년비 버그 수정 → GLS 발행 · **S2** 입력 확장 |

| 유동성 카드 한 줄 요약 · 누르면 점수 · 해석 · 서버 저장 분석 팝업 | ①② | **S4** |

## 2. 조각

### S1 — 주간 전년비 버그 수정 → GLS 발행 (진행 중)

- 원인: 전년비 변환이 「정확히 1년 전 같은 날짜」만 찾아 **주간(수요일) 계열의 짝이 없었다** → 은행 신용 전년비 결측 → 신용 유동성 50% → GLS 50%(보류).
- 수정: 1년 전 **±3일** 안의 가장 가까운 점. 월간은 그대로 정확히 맞는다.
- ⭐ 운영 데이터로 확인(읽기 전용): 신용 65%(61.5) → **GLS 50.4 · 커버리지 65% · 🟡 낮은 신뢰로 발행**. 같은 날 ChatGPT 모니터 52.
- 배포 뒤 첫 계산: 다음 수집(대시보드 「지금 수동 수집」 또는 06:00 자동).

### S2 — 유동성 입력 확장: 판정을 단단하게 (커버리지 65% → 목표 90%+)

| 하위 점수 | 지금 | 붙일 것 | 출처(무료) | 효과 |
|---|---|---|---|---|
| 자금시장(§15) 35% | SOFR−IORB | **레포 안정성** = SOFR 99백분위 − 1백분위 · **자금 변동성** = SOFR 일간 변화 20일 실현변동성 | FRED `SOFR99`·`SOFR1`(2018-04~) · 기존 `sofr` + `realizedVolBp` | 35 → **65%** 발행 |
| 재무부(§14) 30% | TGA 변화 | ⚠ **입찰 응찰률이 운영에 0행 — 원인 확인됨(9/13 22:43 수집)**: 워커 → fiscaldata.treasury.gov가 **525(TLS 핸드셰이크 실패)·시간 초과**로 4계열 전부 실패. 로컬은 성공. **우회 경로부터**(S2 첫 일) · 순발행 압력 = 시장성 국채 총액 3개월 변화 · 바이백 | Fiscal Data MSPD 합계 · Buybacks (⚠ 워커에서 막힘) | 30 → **65%** 발행 |
| SRF 이용 | — | ⚠ `RPONTSYD`는 거의 매일 0 → 10년 창 흩어짐(MAD)=0이라 **정규화 불가** — 결측 이유로 남긴다 | FRED | — |
| 결과 | GLS 65% | 재무부·자금시장이 발행되면 **GLS 100% 구성** | | |

- ⚠ 새 측정은 명세가 정하지 않은 자리(레포 안정성의 정의)라 **Woodsman v0 가정**으로 설계서 12-2에 적는다.
- ⚠ H.4.1 TGA는 **주간 평균**, 우리 `tga`(WDTGAL)는 **수요일 잔액**이다 — 둘 다 맞고 정의가 다르다. 카드에 명시한다(ChatGPT 9/13 보고서 $883.3B vs 우리 $843.7B).

### S3 — 파도: 오늘의 기사 (바람 바로 아래 · 운영자 결정)

- 자리: `macroStrip`(바람) → **`waves`(파도)** → `tide`(조류). 가로 한 줄 5~6건, 낮게.
- 자동: **연준 공식 RSS**(의장·이사 연설 · FOMC 성명 · 의회 증언) · **BLS CPI 발표(Atom)** — 공공 저작물. 수집 때 함께 받는다.
- 수동: 관리자 입력 — 유가·지정학·환율·정책 충격(링크 · 날짜 · 출처 · 한 줄 요약 · 분류).
- ⚠ 저작권: **본문을 싣지 않는다** — 제목 · 날짜 · 출처 링크 · 우리 요약만. 분류: 금리 · 물가(CPI) · 연준(FOMC·발언) · 유가 · 지정학 · 환율.
- ⚠ 원칙 ③: 기사를 점수로 바꾸지 않는다. 사건은 날짜와 출처로 지표와 같은 시간축에 잇는다.

### S4 — 유동성 카드: 한 줄 요약 · 점수 상세 · 해석 팝업 (운영자 결정 2026-09-14)

- 카드 아래 **한 줄 요약** — 프로그램이 쓴다(점수 · 방향 · 가장 크게 끌어올린/내린 계기). 예: 「유동성 50 · 보합 — 신용(62)이 받치고 금리시장(40)이 누른다」.
- 카드를 누르면 **점수 상세**(하위 계기 · 기여도 · 결측 이유 · 기준일) → 「해석」을 누르면 **팝업**.
- 팝업 = ① 우리 계산의 해석(프로그램 문장) ② **그날의 분석** — 관리자가 붙여넣은 일일 보고서(저장: 서버 · 마크다운 → 정화 HTML, 기존 글 경로).
- ⚠ **운영자 결정**: 점수는 **우리 계산**으로 낸다. 외부 보고서(ChatGPT 모니터)에서는 **출처 있는 사실과 해석 문장만** 싣고, **산식 없는 점수·Confidence %는 뺀다**(개발요구서 v2 원칙 유지).
- ⚠ 「한 줄 결론」은 관리자가 따로 적는다 — 보고서 본문에서 자동으로 뽑지 않는다.

### S5 — 산장 (원칙 ⑦) — 조건 초안 확인 뒤

- `설계_홈_섹션계획.md` §3. 국채 실현변동성 점수 · GLS 방향 · 스트레스 · 지속성. 백테스트로 문턱 교정.

## 3. 순서의 이유

1. **S1이 먼저** — 코드 한 줄짜리 버그가 앞줄 판정 전체를 막고 있었다. 가장 싸고 효과가 크다.
2. **S2가 S4보다 먼저** — 팝업이 보여 줄 「점수 상세」가 결측투성이면 해석이 결측을 설명하는 글이 된다.
3. **S3은 S2와 독립** — 기사 파이프라인은 점수와 섞이지 않는다. S2가 길어지면 S3을 먼저 배포해도 된다.
4. **S5는 문턱 확인 뒤** — 조건이 틀리면 나무꾼의 태도가 틀린 신호를 낸다.
