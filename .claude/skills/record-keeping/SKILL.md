# record-keeping — 기록이 없는 자리는 추측이 채운다

## 왜 이 스킬이 있나

운영자(2026-09-27): 「과거의 기록이 없으면 hallucination 유발 가능성이 높습니다. 항상 기록이 중요합니다.
판단의 내용, 개선 내용, 객관적인 근거 등.」

다음 세션은 **기록만 보고** 출발한다. 기록이 빠진 자리는 그럴듯한 추측으로 채워지고, 그 추측이 사실처럼 굳는다.
실제 예: 9/19~9/25 배포 10건이 `/admin/releases`에 안 남아 효과 판정이 겹친 배포를 못 알아봤다(9/27에 채움).

## 끝내기 전에 확인할 것 — 빠진 칸이 있으면 채우고 끝낸다

| 무엇이 있었나 | 어디에 남기나 | 무엇을 적나 |
|---|---|---|
| **판단·결정** | `web/CHANGELOG.md`(코드) · `docs/`(설계) | 무엇을 골랐나 · **버린 선택지와 이유** · 누가 정했나(운영자 결정이면 그 말을 따옴) |
| **개선·변경** | `web/CHANGELOG.md` 모듈별 | 왜(무엇이 문제였나) → 무엇을 → 되돌리면 안 되는 것은 ⚠ |
| **연구·분석** | `docs/연구_*.md` + `web/scripts/research/` | 질문 · 자료 원천과 기간 · 방법 · **수치 결과**(출력에서 옮김) · 한계 · 재현 명령 · 입력 스냅숏 |
| **객관적 근거** | 위 문서 안 | 1차 출처(기관·논문·공식 문서) URL · 날짜 · 무엇이 일치/불일치하는지 |
| **배포** | CHANGELOG 「배포 전 가설」 → `/admin/releases`(release-log 스킬) → 「확인」 절 | 가설은 배포 전에, 결과는 배포 뒤에 **따로** |
| **사고·실수** | CHANGELOG | 증상 → 원인 → 결정 → 재발 방지 (내 실수도 숨기지 않는다) |
| **남은 일** | 기억 `pending-*.md` | 다음 세션이 어디서 시작하나 |
| **운영자의 새 원칙** | 기억 + 설계서(`docs/woodsman_개발요구서_v2.md`) + 필요하면 스킬 | 원칙 문장 · 이유 |

## 규칙

- ⚠ **숫자는 출처 없이 적지 않는다.** 스크립트 출력·API 응답·공식 문서에서 옮긴다. 옮긴 곳을 같이 적는다.
- ⚠ **사후에 정한 것은 사후라고 적는다**(기준·가설). 사후 기록을 사전 기록처럼 쓰지 않는다.
- ⚠ **없는 가설·근거를 지어 채우지 않는다.** 빠진 것은 「빠졌다」고 적는다 — 빈칸이 지어낸 칸보다 정직하다.
- 결과가 그럴듯하지 않으면(상관 ±1.00, 0% 같은) **기록하기 전에 의심하고 다시 잰다.** 그 과정도 기록한다.
- 기록은 커밋한다. 로컬에만 있는 기록은 다음 세션에 없다.

## 하지 않는 것

- 기록을 핑계로 보고를 길게 쓰지 않는다. 보고는 짧게, 기록은 파일에.
- 결과를 가설 칸에 적지 않는다.
