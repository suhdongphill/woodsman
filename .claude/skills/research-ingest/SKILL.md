# research-ingest — 원자료 → 지식

운영자(2026-11-15): 「주도주 분석, 모델 분석 아이디어를 Archiving할 Vault를 docs와 별도로 — 제가 archiving 시킨 것을
ingest해서 docs에 지식을 생성하는 구조로 연구」. 볼트 위치는 운영자가 고름(새 Obsidian 볼트).
구조와 규칙은 `D:\Woodsman\Research\README.md`가 기준이다 — 먼저 읽는다.

## 절대 원칙

1. ⚠ **원자료(00_Inbox)를 이동·삭제·수정하지 않는다.** .md는 프론트매터에 `ingested: true` · `source_note:`만 병합한다
   (`---` 앞 빈 줄은 지워도 된다 — Investor `/tag` 사례). PDF·이미지는 같은 이름의 사이드카 `.md`로 표시한다.
2. ⚠ **docs는 공개 저장소다.** 원문 전문·긴 발췌·유료 리포트 본문을 docs에 옮기지 않는다. 우리가 쓴 정리 + 15단어 이내 인용 + 출처.
   SNS 계정 평가·채널 평가도 docs에 쓰지 않는다(브리핑 원칙과 같다).
3. **지어내지 않는다.** 원자료에 없는 수치·날짜를 채우지 않는다. URL만 있고 본문이 없으면 열어 읽고, 못 열면 「못 읽음」으로 남긴다.
4. T3·T4(뉴스·유튜브·블로그)만 근거인 주장은 idea `status`를 `채택`으로 올리지 않는다 → `/evidence`로 1차 출처를 찾는다.
5. **반대 근거 칸을 비워 두지 않는다** — 찾지 못했으면 「찾지 못함(무엇을 찾아봤나)」.
6. 사이트 지표·모델·화면을 바꾸는 일은 이 스킬에서 하지 않는다. docs에 「후보」로 적고 운영자에게 알린다(변경은 하나씩 배포).

## 절차

1. `D:\Woodsman\Research\00_Inbox\**`에서 `ingested: true`가 없는 파일(사이드카도 확인)을 모은다. 계획을 표로 보여 준다(파일 · 주제 · 만들 노트).
   5개 넘으면 승인을 받고 진행한다.
2. 파일마다 `_templates/source.md` 틀로 `10_Sources/<YYYY-MM-DD> <짧은 제목>.md`를 만든다. 주장은 **검증 가능한 명제**로 쪼갠다.
3. `20_Ideas`의 기존 카드와 대조한다 — 맞는 카드가 있으면 `sources`·근거·반대 근거를 더하고, 없으면 `_templates/idea.md`로 새 카드(`status: 탐색`).
   이미 있는 사이트 연구(`docs/연구_*.md` · 설계서)와 겹치는지 grep으로 확인해 카드에 적는다.
4. 원자료 프론트매터에 `ingested: true` · `source_note: "[[10_Sources/…]]"`를 병합한다.
5. 카드가 `검증중` 이상이고 근거가 충분하면 `30_Synthesis` 초안 → `docs/연구_<주제>_<YYYY-MM-DD>.md`(기존 주제 문서가 있으면 그 문서 갱신).
   docs 문서 끝에 「출처」(URL·발표일·확인일·등급)와 「연구 볼트 경로」(카드 이름)를 남긴다. docs 쪽 변경은 커밋 대상이다 — 커밋은 운영자가 말할 때.
6. 마지막에 보고: 새 Source n · 갱신/새 Idea · docs 반영 · `/evidence`가 필요한 주장 · 사이트 반영 후보.
