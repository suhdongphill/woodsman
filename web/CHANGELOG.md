## 2026-08-02 — 모의 투자임을 밝히고, 투자일지를 실제로 고칠 수 있게

### 가장 큰 문제: 가상 매매가 실계좌처럼 보였다

`/portfolio`가 **"실제로 운용 중인 계좌입니다"**라고 적고 있었다. 실제로는 가상 매매다.
이 상태로 색인이 열리면 나중에 진짜 기록을 올려도 신뢰를 회복할 수 없다.

다만 문구는 **사과가 아니라 설명**이어야 한다. 매매·납입은 가상이어도 **종목 시세는 실제
시장가격**이라, 원칙대로 목표 비중을 채워 가는 과정은 정직하게 보여줄 수 있다.

- `lib/data-mode.ts` — `PAPER`(모의) / `LIVE`(실계좌). ⚠ 기본값은 `PAPER`.
  설정을 못 읽었을 때 실계좌로 보이면 안 된다. 테스트가 "믿지 마세요" 같은 표현을 막는다.
- 계좌 숫자가 나오는 **모든 화면**(홈·포트폴리오·투자일지)에 표시가 함께 나간다.

### 투자일지가 목업이라 고칠 수 없었다

화면이 `lib/mock.ts`를 읽고 있어서 **저장 버튼이 아무 일도 하지 않았다.** 시드가 D1에
같은 데이터를 넣어 두었는데도 화면은 파일을 보고 있었다. 주력 콘텐츠가 이 두 가지라
못 고치면 사이트가 굴러가지 않는다.

- `features/journal/{repository,schema,actions}.ts` + 폼 2종 → D1 읽기·쓰기·삭제
- 공개 화면(`/`, `/journal`, `/portfolio`)도 DB를 읽는다. 전부 `force-dynamic`.
- ⚠ 날짜는 **정오(UTC)**로 저장한다. KST 자정으로 넣으면 앞 10자를 자르는 화면에서
  하루가 밀린다(07-28 기록이 07-27로 보였다). 시드 생성기도 같은 규칙으로 맞추고
  기존 행을 정규화했다.

### ⚠ 통화를 섞어 더해서 비중이 통째로 틀렸다

목표 대비 현재 비중을 처음 그렸을 때 **성장 버킷이 0.1%**로 나왔다. 달러 종목의 평가액
(191.2×40)이 원화 종목(34,200×320)보다 세 자릿수 작아서 반올림에 묻힌 것이다.

- `SiteConfig.usdKrwRate` 추가(기본 1,350) → `/admin/settings`에서 고친다.
- `allocation.holdingValueKrw()`를 반드시 거쳐서 넣는다. 화면에 "1달러 = N원 기준
  (실시간 시세가 아닌 기준 환율)"이라고 밝힌다.
- 고친 뒤: 성장 33%(목표 32%) / 인컴 49.6%(38%) / 방어 17.4%(30%) · 구성 완료 87.4%.
- 회귀 테스트가 **옛 버그를 그대로 재현**해 둔다(환산 없이 넣으면 1% 미만으로 묻히는 것).

### 목표까지 얼마나 채웠는지를 보여준다

목표 배분만 보여주면 이미 그렇게 굴리는 것처럼 읽힌다. 실제로는 매달 넣는 돈으로 조금씩
채워 간다. 점선(목표) 위에 막대(현재)를 겹쳐 그리고, 부족한 자리를 `%p 남음`으로 적는다.
⚠ "무엇을 얼마나 사라"는 계산은 하지 않는다 — 차이까지만 보여주고 판단은 사람이 한다.

### 티스토리를 주소가 아니라 콘텐츠로

`suhdp.tistory.com/2`를 그대로 찍고 있었다. **주소는 읽는 사람에게 아무 정보가 아니다** —
무슨 글인지 모르니 누를 이유가 없다. 글 제목과 요약을 보여주고 카드 전체를 누르게 했다.
제목·요약은 `/admin/settings`에서 고친다.

### 사이트 기본값 화면 (`/admin/settings`)

처음 개발할 때 코드에 박아 둔 값을 화면에서 고친다 — 모의/실계좌, 기준 환율, 홈 문구,
티스토리 대표 글, 문의 메일·블로그·RSS 주소. 빈 칸은 코드 기본값으로 되돌아간다.

- ⚠ 티스토리 주소는 `/go/*`의 목적지다. `sanitizeUrl`을 통과 못 하면 저장하지 않는다.
- 문의 메일을 `suhdp@naver.com`으로 변경. **다섯 곳에 하드코딩돼 있던 것**을
  `site-links.ts` 상수 하나로 모았다.

### AI 호출에 제한 시간

느린 제공자 하나가 화면을 붙잡고 있으면 사용자는 고장으로 받아들인다.
제공자별 기본값(Groq 12초 ~ DeepSeek 90초)과 모델별 재정의(추론 모델 120초)를 두고,
넘으면 끊고 **다음 후보로 넘어간다.** 관리자 화면이 1순위 제한 시간과 최악 대기 시간을 보여준다.
⚠ 제한 시간 없는 제공자가 생기지 않도록 테스트가 막는다.

### 개발 환경 함정

⚠ `npm run dev`가 떠 있는 상태로 `npm run build`를 돌리면 Windows에서 `.next`가 깨진다
(EPERM / `_buildManifest.js` 없음 → 화면 전체가 500). **빌드 전에 dev를 끈다.**

## 2026-08-02 — 키를 프로그램이 `.env`에 써 준다 · www 정본화 · DeepSeek 추가

### 요구사항이 뒤집힌 지점

처음에는 "화면에서 키를 받지 않는다"로 만들었다. 운영자의 요구는 **"내가 등록한 것을
프로그램이 `.env`에 저장해서 매번 다시 입력하지 않게"** 였고, 그건 입력창을 없애라는 뜻이 아니었다.

그래서 **로컬 개발 서버에서는 화면에서 입력받아 프로그램이 `.env`에 직접 쓴다.**
⚠ 배포본(Workers)에는 파일 시스템이 없어 `.env`라는 파일이 존재할 수 없다. 이건 정책이 아니라
물리적 제약이라 화면에도 그 이유를 그대로 적었다. 배포본 반영은 여전히 `npm run ai:sync`다.

- `lib/env-file.ts` — `.env` 텍스트 변환(순수 함수). AI 전용이 아니게 되어 `lib/ai/`에서 옮겼다.
  - 이미 있는 키는 **그 줄만** 바꾼다(주석·순서 보존)
  - ⚠ `OPENAI_API_KEY`와 `OPENROUTER_API_KEY`처럼 이름이 겹쳐도 다른 줄을 건드리지 않는다
  - 붙여넣기에 딸려오는 앞뒤 공백·줄바꿈을 떼어낸다 — 키 사고의 대부분이 이것이다
- `features/ai/env-writer.ts` — 파일 쓰기. 개발 모드가 아니면 시도조차 하지 않는다.
- ⚠ 폼 상태·에러 메시지에 키 값을 담지 않는다(클라이언트로 직렬화돼 내려간다).
- ⚠ 저장 후 `ai:sync`를 자동으로 돌리지 않는다. 실수로 넣은 키가 곧바로 운영에 올라가지 않게.

### 관리자 계정을 사람이 정할 수 있게 (`scripts/set-admin.mjs`)

최초 시드가 `admin@woodsman.local` + 자동 생성 비밀번호를 썼다. **사람이 정한 적이 없는 계정이라
로그인하려니 뭘 넣어야 할지 알 수 없었다**(실제로 막혔다).

- `npm run admin:set` — 물어보고 받는다(비밀번호는 화면에 찍히지 않는다)
- `npm run admin:apply` — 묻지 않고 `.env`에 적힌 값을 DB에 반영한다.
  프롬프트를 띄울 수 없는 환경용. ⚠ 비밀번호를 명령줄 인자로 받지 않는다.

### 로그인 진입점의 헛돎

로고 더블클릭 → `/login`은 정상 동작했는데, **이미 로그인한 관리자는 홈으로 되돌려 보내져서
"아무 일도 일어나지 않은" 것처럼 보였다.** 갈 곳을 지정하지 않은 관리자는 `/admin`으로 보낸다.

### www가 옛 앱을 띄우던 문제

커스텀 도메인을 apex에만 붙여서 `www.`는 계속 옛 Pages 앱이었다. www도 이 Worker로 받고,
`next.config.ts`에서 정본(apex)으로 301 이동시킨다 — 색인이 열린 뒤라 중복 콘텐츠가 실제 문제다.

- ⚠ `/:path*` 규칙 하나로 묶으면 **루트 요청에서 치환이 안 돼 `/:path*` 문자열이 그대로
  Location에 나간다.** 루트와 하위 경로를 나눠 적었다.

### DeepSeek 추가

무료 티어가 아니라 '아주 싼 유료'라 `free`로 표시하지 않았다(무료로 두면 상한 없이 돈다).
대신 카탈로그에서 Claude보다 앞에 놓아 깊은 추론 작업에서 먼저 시도된다.
⚠ 요금은 직접 확인하지 않아 `null`로 뒀다.

### 그 밖에

- 보안 테스트가 **내 테스트 픽스처를 진짜 Groq 키로 오인해 잡았다.** 감지기가 도는 걸 확인한
  셈이라 픽스처를 명백한 가짜 값으로 바꿨다.
- `/admin/ai`의 설명이 "화면에서 편집할 수 없습니다"로 남아 있었다 — 화면과 어긋나 고쳤다.
  화면을 바꿨으면 문구도 같이 봐야 한다.
- 운영·로컬 D1에 DeepSeek 제공자 행 추가(행이 없으면 "상한 없음"으로 동작한다).

## 2026-08-02 — ⚠ 도메인 이전: `portfolio-solutions.net`

`wrangler.jsonc`의 `routes` 한 줄을 켜고 배포했다. 기존 앱을 교체했다.

- ⚠ 커스텀 도메인을 켜면 **`workers.dev` 주소가 자동으로 꺼진다**(지금 404).
  중복 색인이 안 생기는 건 이득이지만 **폴백 주소도 같이 사라진다** — 도메인 쪽에 문제가 생기면
  대시보드에서 workers.dev를 다시 켜야 한다.
- ⚠ 도메인만 옮기고 끝내면 안 된다. 시크릿 두 개를 같이 바꿨다.
  - `AUTH_URL` — 다르면 로그인 콜백이 깨진다
  - `SITE_URL` — 비어 있으면 robots.txt가 **전체 색인 차단**으로 동작한다
- **이 시점부터 검색 색인이 열렸다.** 그전까지 일부러 닫아 뒀다(미리보기 주소가 색인되면
  나중에 중복 콘텐츠로 정리하기 어렵다).

검증(운영 도메인 기준): 홈 200 · `/login` 200 · `/admin/*`는 로그인으로 307 ·
robots.txt가 `Allow: /` + 실제 도메인 sitemap · `/go/tistory` → `https://suhdp.tistory.com/2` 302 ·
그 클릭이 D1 `OutboundClick`에 실제로 기록됨(읽기·쓰기 동시 확인).

운영 D1에 `AiProvider` 행이 5개뿐이라(카탈로그에 OpenAI가 늦게 추가됨) 누락된 한 행을 넣었다.
행이 없으면 코드가 "활성·상한 없음"으로 보는데, 유료 제공자에 상한이 없는 상태를 만들지 않기 위해서다.

## 2026-08-02 — AI 모듈: 페르소나 · 라우팅 · 키 등록 경로

여러 AI 제공자(무료 포함)의 키를 등록해 두고 **토큰을 아껴 쓰는 것**이 목표였다.
핵심 판단 세 가지를 각각 다른 모듈로 나눴다.

### `lib/ai/catalog.ts` — 무엇을 부를 수 있나 (순수 데이터)

제공자·모델·요금표. ⚠ **키 '값'은 이 파일에 없다.** 어느 env 변수에 넣어야 하는지만 안다.

- Claude 모델 ID·요금은 Anthropic 공식 값(Opus 5 $5/$25, Sonnet 5 $3/$15, Haiku 4.5 $1/$5).
- ⚠ 나머지 제공자는 `price: null`. **모르는 요금을 0으로 적지 않는다** — "무료인 줄 알았는데
  청구"가 된다. 화면은 null을 "요금 미확인"으로 표시한다.
- ⚠ 제공자 목록의 출처는 여기 하나다. `seed-data.ts`의 `aiProviderCatalog`가 이걸 파생해서 만든다
  (전에는 두 곳에 따로 적혀 있어서 카탈로그에 추가해도 시드에는 안 들어갔다).

### `lib/ai/persona.ts` — 어떻게 물을 것인가

화면 기능마다 페르소나가 다르다. 같은 프롬프트를 쓰면 어느 화면에서든 똑같은 "종합 분석"이 나온다.

- 기업분석 = 편입 논리(thesis)를 쓰는 운용자 / 차트 = 예측하지 않는 관찰자 /
  CANSLIM = 의견 없는 채점자 / 투자일지 = 내용을 만들어내지 않는 편집자.
- ⚠ 공통 규범 `WOODSMAN_DOCTRINE`이 **항상 맨 앞에** 붙고 개별 페르소나가 덮어쓸 수 없다.
  매수·매도 권유 금지, 목표주가 금지, 방향 단정 금지, 없는 수치 생성 금지.
  이건 취향이 아니라 `/disclaimer`에 쓴 문장과 직접 연결된 약속이다. 테스트가 지킨다.

### `lib/ai/context.ts` — 무엇을 먹일 것인가

"TSMC 분석해줘"는 어떤 모델이든 검색하면 나오는 일반론을 뱉는다.
이 사이트가 낼 수 있는 값은 **운영자의 계좌 맥락 안에서 본 그 종목**이라, 기능별 배분·해당 종목이
맡은 역할·이미 적어 둔 편입 논리·최근 판단 기록을 같이 넣는다.

- 이미 편입된 종목은 "기존 논리가 여전히 유효한가"를 묻고, 미편입이면 "어느 기능을 맡을 수 있나"를 먼저 묻는다.
- ⚠ 빈 값을 빈칸으로 두지 않고 "자료 없음"으로 채운다. 빈칸을 두면 모델이 지어낸다.
- ⚠ 계좌의 **절대금액·개인정보는 넘기지 않는다.** 비중과 논리만 넘긴다.
- 차트 분석에는 계좌 맥락을 넣지 않는다 — 관찰에 편향이 생긴다.

### `lib/ai/routing.ts` — 어디로 보낼 것인가

토큰 절약의 실제 지렛대는 키를 어디 두느냐가 아니라 **무엇을 어디로 보내느냐**다.

- 무료 → 유료 순. 작업이 요구하는 급을 만족하는 **가장 싼 모델**을 고른다
  (CANSLIM은 balanced면 되므로 Claude에서 Opus가 아니라 Sonnet이 잡힌다).
- 키가 없는 제공자는 후보에서 뺀다 — 눌러도 실패하는 경로를 만들지 않는다.
- ⚠ 월 토큰 상한을 넘긴 제공자도 뺀다. 유료 제공자에 상한이 없으면 실수 한 번이 그대로 청구서다.
  화면이 "유료인데 상한 없음"을 붉게 경고한다.

### `features/ai/` — 화면과 DB

- `repository.ts` — DB에는 **상태만**(활성 여부·상한·사용량) 둔다. 카탈로그를 복사해 두지 않는다.

  "키를 넣었는데 계속 미설정"으로 보인다.

### `scripts/sync-ai-secrets.mjs` — "매번 입력하지 않게"

요구사항의 답은 화면에 입력칸을 두는 게 아니라 **`.env`에 한 번 적고 밀어 넣는 것**이다.
화면 입력칸을 두면 키가 폼 → 서버 액션 → DB → 로그를 타고 돌아다니고, 이 저장소는 공개라
한 번 새면 되돌릴 수 없다.

```
npm run ai:sync     # .env에 값이 있는 키만 Cloudflare 시크릿으로 업로드
```

- ⚠ 값은 stdin으로 넘긴다(명령줄 인자는 프로세스 목록에 노출된다). 화면에는 변수명과 길이만 찍는다.
- `.env`에 비어 있는 키는 건드리지 않는다 — 서버에 이미 올라간 값을 지우지 않기 위해.
- 실패하면 종료 코드를 세운다. 조용히 넘어가면 그 제공자는 배포본에서 계속 "미설정"이다.

## 2026-08-02 — ⚠ 런타임에서 Prisma 제거, D1 직접 사용 (배포가 조용히 죽던 문제)

### 무슨 일이 있었나

배포는 성공하고 화면도 떴는데 **모든 DB 호출이 실패**하고 있었다.
그런데 실패 결과가 "설정이 비어 있는 정상 상태"와 똑같아 보여서 알 수가 없었다
(커뮤니티 닫힘 = 정책이기도 하고 DB 실패 시 폴백이기도 했다).

D1에서 `communityEnabled=1`로 바꿔도 사이트가 안 바뀌는 걸 보고 확정했다.

### 원인 (셋이 겹쳤다)

1. `prisma-client-js` 생성기는 **바이너리 쿼리 엔진**을 찾는다 → Workers엔 실행 파일이 없다
2. `prisma-client` + `runtime="cloudflare"`로 바꾸니 **WASM 엔진**을 찾는데,
   OpenNext가 만든 Worker 번들에 그 .wasm이 포함되지 않는다
   (opennextjs-cloudflare #471 / prisma #23457 — 2026-08 기준 **미해결**)
3. `getCloudflareContext()`를 동기로 부르면 정적 생성 단계에서 실패한다 → `{ async: true }` 필수

### 결정: Prisma는 스키마·마이그레이션 도구로만 남긴다

런타임 쿼리는 **D1 바인딩을 직접** 쓴다(`src/lib/d1.ts`). 우리가 쓰는 쿼리는 6개뿐이라
ORM을 억지로 얹을 이유가 없었다. 얻은 것:

- 배포가 **실제로 동작한다** (가장 중요)
- `next.config.ts`의 우회 두 개(WASM 실험 플래그, 파일트레이싱 제외)가 **전부 불필요해져 삭제**
- 의존성 3개 제거(`@prisma/client`, `@prisma/adapter-d1`, `@auth/prisma-adapter`), 번들 축소
- 로컬/운영 DB 경로가 **하나로 통일**됨 (`next dev`도 로컬 D1을 쓴다)

`prisma/schema.prisma`는 여전히 스키마의 원본이고, 마이그레이션도 계속 Prisma로 만든다.

### 재발 방지

- ⚠ **조용한 폴백을 만들지 않는다.** DB에 못 붙는 상태가 "정상"처럼 보이면 안 된다.
  실패는 던지고, 호출부가 로그를 남긴 뒤 안전한 기본값으로 응답한다.
- ⚠ 도메인 쿼리는 각 기능의 repository 모듈에 모은다
  (`features/auth/repository.ts`, `lib/outbound-repo.ts`).
- Auth.js 어댑터는 뗐다. 지금은 JWT + Credentials라 필요 없다.
  소셜을 열 때는 `@auth/d1-adapter`를 붙이면 된다(스키마에 Account/Session은 이미 있다).

### 클릭 집계가 적게 잡히던 문제

`/go/*` 리다이렉트가 캐시돼 두 번째 호출부터 Worker가 실행되지 않았다(3회 중 1회만 집계).
`next/navigation`의 `redirect()` 대신 `cache-control: no-store`를 붙인 Response를 직접 돌려준다.
검증: 7회 호출 → 정확히 7 기록.

## 2026-08-02 — Phase 2: 인증 · 권한

### `lib/auth.config.ts` · `auth.ts` — 설정 분리

- 미들웨어는 Edge에서 돌아 Prisma·bcrypt를 못 씁니다. 그래서 Edge 안전판(`auth.config.ts`)과
  완전판(`auth.ts`)으로 나눴습니다.
- ⚠ **`trustHost: true`** — 없으면 자체 호스팅 프로덕션에서 Auth.js가 모든 요청을
  `UntrustedHost`로 막아 로그인이 통째로 실패합니다. 개발 서버는 localhost를 자동 신뢰해
  드러나지 않고, 프로덕션 빌드로 띄워야 재현됩니다. 배포 시 `.env`의 `AUTH_URL`을 함께 설정하세요.
- 세션은 JWT 전략(Credentials가 DB 세션을 지원하지 않고, 미들웨어가 DB 없이 role을 읽어야 함).

### `lib/access.ts` · `middleware.ts` — 접근 정책

- 판단을 순수 함수로 분리해 미들웨어와 서버 컴포넌트가 같은 규칙을 씁니다.
- ⚠ Next.js는 `matcher`를 빌드 타임 리터럴로만 읽어 상수를 참조할 수 없습니다. 그래서
  `access.test.ts`가 미들웨어 소스를 읽어 두 곳이 어긋나지 않는지 대조합니다.
- ⚠ `/admin`은 미들웨어 + 레이아웃(`requireAdmin`) 이중 확인. matcher 실수 한 번에 전
  구역이 열리지 않도록.

### `features/auth/` — 로그인·회원가입

- ⚠ 가입은 항상 `USER`. `role`이 스키마에 없어 폼으로 승격할 수 없습니다.
- ⚠ 로그인 실패 사유를 구분해 알려주지 않습니다(계정 존재 여부 노출 방지).
- ⚠ 복귀 경로 `next`는 같은 사이트 절대경로만 허용(오픈 리다이렉트 방지).
- `"use server"` 파일은 async 함수 외에는 export할 수 없어 상수를 `form-state.ts`로 뺐습니다.

### `next.config.ts` — Windows 빌드 실패 대응

- ⚠ Prisma 생성 클라이언트를 파일 트레이싱에서 제외합니다. `src/generated/prisma`에
  번들된 dotenv의 `os.homedir()`를 Next 트레이서가 정적 평가해 홈 디렉터리 전체를 glob하고,
  Windows의 접근 불가 정션(`Application Data`)에서 EPERM으로 빌드가 죽습니다.
  node_modules 안이면 기본 무시 규칙에 걸리는데, `src/` 아래라 비껴갑니다.
- Next 업그레이드로 이 훅이 안 먹으면 빌드가 다시 EPERM으로 실패하므로 조용히 망가지진 않습니다.
